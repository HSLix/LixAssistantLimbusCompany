# Stage 3 垂直步骤草案

状态：已确认并发布为 #324–#329；正式步骤文档见 docs/stage-3-implementation-slices.md。Spec：[GitHub #323](https://github.com/HSLix/LixAssistantLimbusCompany/issues/323)，关联阶段跟踪 #312。

## 1 — Mac 贯通 pi、图片与受限工具的最小调用

**Blocked by:** None — can start immediately.

**What it delivers:** 在 Mac 上从 LALC 的 Python 调用入口启动 pi，使用临时连接参数和内存密钥，真实模型收到图片并调用一个受限的源码读取工具，返回最终回答。记录实际请求、图片、工具交换和结束结果，固定此次验证通过的跨平台 pi 版本。此步骤只证明接入可行，不宣称已完成修复。

- [ ] 验证 RPC、扩展加载、实际图片输入、受限工具回调、事件留存和密钥传递，不仅检查版本或帮助。
- [ ] 验证可以关闭框架默认终端、通用文件写入、未授权扩展/配置引入的工具与上下文；不把个人 pi 配置作为接入前提。
- [ ] 验证模型请求计数、终止与取消所需事件/接口；检查是否存在框架内部请求和重试，不静默绕过后续请求上限或失败即停止的约定。
- [ ] 保留按日期和 UUID4 分组的实际交互记录；不记录密钥，不在持久配置中保存明文凭据。
- [ ] 以真实模型调用和可检查日志为结果；若 pi 不能满足必要边界，记录具体阻碍并回到选型讨论，不自行更换框架或供应商。

## 2 — 从 Default Manifest 完成受限单 Component 修复

**Blocked by:** 1.

**What it delivers:** 开发者通过独立修复 CLI 指定一个现有 Component，提供问题、异常和截图；LALC 从 Default 重建 Developer Candidate，真实模型只修改目标源码，调用现有 Validator 迭代，最终输出源码、Diff、校验结果与完整日志。

- [ ] 来源和目标检查先于候选清空；没有有效 Default、加载失败、目标缺失不启动 Agent、不破坏旧草稿、不改选历史 Manifest。
- [ ] 有效启动替换已有 Developer Candidate，可读全部候选文件但只写指定 Component；拒绝任意路径、其他源码及候选 Manifest 写入，不自动 Publish 或改变 Default。
- [ ] 源码读取与修改复用 pi 的 read/edit，通过扩展或文件操作接口实施权限检查，不重写文本替换或编辑引擎；不把工作目录当作隔离，不开放通用 write 或终端工具。
- [ ] 接收初始截图/异常/问题描述和 LALC 编写约束；不引入游戏模拟或候选自动运行。
- [ ] Validator 反馈实际回到模型；结束时重新校验最终源码，输出实际 Diff，不把校验通过称为行为修复成功。
- [ ] 默认 20 次请求并支持本次设置；超限、模型错误和取消停止并保留产物，信息不足时最终回答说明缺少什么并结束。
- [ ] 完整日志和原始/最终产物在数据目录留存，后续重建候选不会抹掉前次记录；错误、取消与校验失败也有明确结束原因。

## 3 — Agent 使用完整的 Asset、Trusted Action 与游戏观察工具集

**Blocked by:** 2.

**What it delivers:** 在实际修复调用中，Agent 发现 Asset 逻辑名、查看目录标签及一张或多张图片，查询应用动作契约，取得当前游戏截图并现场裁剪新增 Asset，再据此修改指定 Component 和调用 Validator。Windows 验证实时画面与裁剪，Mac 验证只读工具；除受限新增外不修改已有素材，不执行游戏控制。

- [ ] 分别提供全局逻辑名文字树、指定逻辑名下全部文件名及标签内容、完整逻辑名/完整哈希选图三个只读工具。
- [ ] 图片工具一次支持一张或多张，模型实际收到图片并能对应逻辑名与哈希；日志保留图片和实际返回。
- [ ] 标签缺失如实返回，不修复元数据；非法逻辑名、越界路径、哈希前缀与内容不符被拒绝。
- [ ] 一个动作查看工具从实际注册表和现有签名/docstring 派生全部动作的分类、参数和返回说明，不暴露实现源码、不执行动作。
- [ ] 自动化检查和真实模型调用均确认只读结果与写入权限，原图、旧标签及动作注册保持不变。

- [ ] 实时截图复用唯一 Target Window 与焦点检查，返回实际新图及尺寸，不伪装旧图为当前状态。
- [ ] 裁剪接收逻辑名、客户区像素区域和可选标签，每次重新截图后裁剪，不从保存截图裁剪、不开放文件导入或任意输出路径。
- [ ] 新哈希保存新图、标签与来源，缺省标签明确为空；同名同哈希直接复用原图和旧标签，明确返回已存在，不覆盖其他映射。
- [ ] 新 Asset 无需 Publish 即可被共享库读取，失败或取消保留新增产物；开发者裁剪/tag 工具的标签替换语义不变。
- [ ] 不增加点击、按键、候选执行或运行中 Working Manifest 接入；不支持的平台如实报告工具不可用。
- [ ] 除自动化契约检查外，Windows 上以真实模型完成截图和裁剪调用，保留新图及重复裁剪不覆盖标签的实测证据。

## 4 — 持久模型设置与 Windows DPAPI 命名密钥用于修复

**Blocked by:** 2.

**What it delivers:** 开发者保存远程服务地址、模型和请求上限后，后续修复直接沿用；Windows 的命名 API key 由 DPAPI 存储并用于实际认证，Mac 开发仍使用临时内存密钥。

- [ ] 普通配置与密钥分离；未设置请求上限时为 20，保存修改供以后沿用，单次覆盖不修改已保存值；本次有效配置固定并记入日志。
- [ ] 连接开发者指定的 llama.cpp 地址/模型，检查服务状态和图片能力并验证实际图片输入；不把未加载与不支持图片混报，不自动换供应商或模型。
- [ ] Windows 实现 DPAPI 命名密钥保存与读取，不限定模型 API key 类型，不预建其他密钥业务；实际认证不要求把明文写入 pi 持久配置。
- [ ] Mac 首版不保存密钥，运行时临时输入；日志、模型上下文、候选文件、明文命令参数和普通配置均不泄露密钥。
- [ ] Windows 完成真实 DPAPI 存取和实际模型认证证据；Mac/替身测试不能冒充 Windows 验收。

## 5 — 开发者准备真实单 Component 缺陷与复现材料

**Blocked by:** None — can start immediately.

**What it delivers:** 准备一个真实游戏中的可重复失败案例，确定只需修改一个现有 Component，保存原始版本、初始截图、异常、输入、复现步骤和预期行为，为最终前后对照提供固定基线。

- [ ] 不是单纯语法错误；原始 Component 在既定前置状态下能够重复表现行为缺陷。
- [ ] 缺陷种子、所需资源和人工准备游戏状态的方法被保存，不依赖已清空的 Developer Candidate。
- [ ] 确定人工如何观察修复成功，以及如何安全重建前置状态；不实现游戏状态模拟或离线行为判定工具。
- [ ] 由开发者选择并提供案例，作为最终 demo 的外部输入；不阻塞前四项的工具开发与接入验证。

## 6 — Windows 集成验收并交付 TA demo

**Blocked by:** 3, 4, 5.

**What it delivers:** 在固定版本 pi 和指定真实模型下，对开发者案例完成一次完整修复。人工审阅发布后，在 Windows 游戏中展示原问题消失，并将可复现说明、交互日志、候选/Diff/校验和游戏前后对照交付 TA。

- [ ] 从 Default 初始化候选，真实模型读取上下文与图片、使用受限工具并完成单文件修订和最终 Validator 校验。
- [ ] Windows 确认实时截图、现场裁剪、重复图片原标签保护及 DPAPI；需要时引用同固定版本/同实现的已留存实测，不要求把不相关操作硬塞进缺陷案例。
- [ ] 人工审阅并沿用既有 Publish/运行流程，保存修复前失败和修复后游戏行为成功的对照；只通过 Validator 不算完成。
- [ ] 核对正式源码、已有 Manifest、原图、旧标签和 Default 的 Agent 写入边界；仅指定候选源码变化与允许的 Asset 新增。
- [ ] 提供启动、配置、工具范围、上限、信息不足/取消/错误、日志定位与人工验收说明，并标明候选会在下次有效启动时重建。
- [ ] 在 2026-10-29 前完成 TA 交付；目标 10 月 28 日完成演示与证据，保留交付余量。未完成的真模型/实机验收明确列出，不以替身填补。

## 依赖与时序建议

- 初始 frontier：1、5。1 是首个技术风险验证；5 可由开发者独立准备。
- 1 完成后做 2；2 完成后 3、4 无相互逻辑阻塞，可按设备可用性安排，不要求多 Agent 并发。
- 3、4、5 均完成后做 6；2 是它们的传递前置，不重复列为直接 blocker。
- 目标节奏：10 月 23–24 日解决最小接入风险；10 月 24–26 日完成修复工具、配置和案例；10 月 27–28 日留给 Windows 集成、真实行为验收与交付。它是排期目标，不是已完成证据。
- 发布时每项单独建单并标记 ready-for-agent，优先建立原生 blocking 关系；不修改或关闭父 Spec #323 或原阶段跟踪 #312。
