# 素材处理

1. 先确认素材逻辑名、用途及已有图片；仅在确有需要时新增或归档移除。共享 Asset Library 的变更会影响其他 Session 和后续匹配，切换 Session 不会撤销；除专用新增／归档工具外，不改既有图片或标签。
2. 匹配保留完整返回结果；多个命中不自动失败、不视为无目标，也不要求全部动作。业务 Step 决定选择和动作，有歧义时用 ctx.log(message, level="warning") 记录歧义及依据，不随意丢弃结果或认定完成。
3. 需要现场区域时获取当前截图，结合原图、坐标网格和同图 OCR 定位。截图会恢复并置前唯一游戏窗口，现场工具仅 Windows 可用。网格等辅助覆盖层不能进入模板或原始证据。
4. game_screenshot 附带完整 OCR，坐标为客户区像素；ocr_error 表示识别失败，不是没有文字。OCR 不支持韩文，分数不证明识别正确。素材尽量避免掺入文字以适应语言变化；必须含文字时可以保存，也应考虑 OCR 能否替代。
5. 保存前调用 preview_crop，检查区域标线图、干净裁剪图和同图匹配。区域不合适就重新预览；符合目标后只用该次 preview_id 调用 crop_asset 保存相同像素，不重新截图或猜测 ID。ID 失效就重新获取。同图匹配不证明跨状态可靠性；同名同哈希复用原图和原标签。
6. 需要时更新 Candidate 中的素材引用；若修改 Workflow，读取 `../validation-and-trial/SKILL.md`，完整 Validate，按需通过明确已发布版本试运行检查实际匹配，不用预览或校验替代游戏验证。
7. 归档移除前确认逻辑名、具体哈希和理由，仅使用 remove_asset；工具失败时先检查原因，不假定已移除。总结实际保存或移除内容及尚未验证的适用状态。
