# 验证与试运行

1. 工具成功不等于完整 Validate 通过。修改 Candidate 后执行完整 Validate，按实际错误继续修正；校验失败仍可修改。Validator 会导入 Python，不是安全沙箱；校验通过不等于真实游戏验证通过。
2. 新修改运行前必须先 Publish 为不可变版本，再用明确 Manifest ID 试运行保存的新代码；不执行可变 Candidate。Publish 不执行、不设置 Default，也不表示运行时永久批准。
3. 按用户要求和验证需要决定是否试运行；仅分析、查看资料不强制修改或发布。试运行期间等待工具结果，不并行修改或操作游戏。
4. 启动拒绝没有 Run ID，不能当作已运行；启动后的结果和 Run 日志才是运行证据。必要时读取日志，失败后依据新证据修订，不无依据反复重试。用户停止运行后总结并等待新指示。
5. 总结实际修改、静态校验、已发布版本、真实运行及未验证事项。不编造工具结果或验收结论；依照常驻最终 JSON 契约判定 revise_success。用户明确要求成功试运行时，未运行或失败不能报告修订任务已完成。
