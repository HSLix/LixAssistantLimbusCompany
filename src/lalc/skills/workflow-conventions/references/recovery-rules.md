# Recovery Rule 编写与排查

- 正常 Connecting／Combat Tips／Now Loading 在 Workflow 集中等待，见同目录 `dispatch-and-wait.md`。Recovery Rule 处理正常业务之外的错误弹窗等外部中断，不把正常加载未完成一律变成异常。
- detect 依据目标异常的独特特征，防止正常画面误触发和不同异常互相误匹配。外观相似、靠文案区分的弹窗优先考虑 OCR；共有背景和 Confirm 按钮不足以区分异常。
- recover 只做当前匹配状态的一次有意义推进，如点击或一段有界等待，留出状态变化时间。不要在规则里循环到整条异常链彻底消失；内部轮询同样必须有界，耗尽可记录当前情况并返回，交执行器重新调用业务入口验证。
- 执行器连续恢复次数默认上限 10，可配置。规则正常返回后计数加一，再重新调用中断入口；再次失败才重新检测。Step 正常返回或 Agent 介入时清零；该上限不能限制尚未返回的 recover 内部循环。
- 唯一匹配才执行规则；歧义、规则自身错误或首次业务失败零匹配会交可用的 Agent，否则结束恢复。不要承诺“没匹配到规则就一定重试”。修复版本 Recheck 的具体交接遵循当前 Runtime 契约。
- 规则可能改变现场。排查反复失败时查看实际规则介入及截图，不默认既有规则一定正确；已确认误匹配才最小修正。保留取消、环境错误和原始异常，不转换为普通业务未达成。
