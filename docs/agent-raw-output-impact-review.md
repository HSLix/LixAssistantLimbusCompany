# Agent 临时原始输出与取消强制推理预检：影响审查

2026-11-01；输入为[已确认决定](agent-raw-output-decisions.md)。源代码检查完成，实施前未执行模型或 GUI 检查。后续实施及实测证据见[实施记录](agent-raw-output-implementation.md)。

## 设计变化

- 过去只展示已完成的回答 / 工具 → 每条模型消息生成期间提供默认收起的临时原始输出区，结束时清空。文字、实际 thinking 和生成中的工具参数可见，不恢复进历史。
- 每轮先单独推理检查连接 / 图片 → 直接执行正式请求，请求从 1 计数；格式纠正仍计入额度。保留设置页手动检查和发送前配置 / 图片元数据校验。

## 已确认影响

- `agent_repair.RepairConversation.run` 及 `check_model_image`：正式循环忽略 message_update；唯一自动预检调用在每轮 run 内。移除该调用与无其他调用者的预检函数，保留 configured_pi、RPC、图片 context 注入、错误诊断和取消清理。
- `RepairLog.record` 同时持久化与通知 GUI；流式快照应先按现有规则脱敏，再仅通知 GUI。使用累计内容避免跨片切分造成文本拼接错误；不把逐 token 快照写入 events.jsonl，也不改变最终消息记录。
- `RepairPage.show_event` / `render`、`new` / `activate_session` / `reload_history`：接入临时区与消息结束、工具开始、错误、重试、取消及空闲收尾；历史重放不显示临时内容。沿用主线程 Signal 更新。
- `RepairChat` 的历史 / Markdown / 工具合并无需改动；临时区独立置于聊天记录下、输入框上，使用只读纯文字与限高滚动，不将模型内容当 HTML。
- `AgentSettingsPage.check` → `agent_diagnostics.check_settings` → 模型列表读取：与自动推理预检无调用关系，保留两种手动检查、不新增推理测试按钮。
- `pi_probe.ts`：删除自动预检专用提示词 / 工具分支，保留请求预算、工具白名单、图片注入和最终格式纠正限权。
- `tests/test_agent_repair_agent.py`、`test_developer_session_agent.py`：原测试将预检计入请求数、快照编号、前缀索引和错误阶段，需同步更新；补充真实 pi + HTTP 替身的流式转发 / 不落盘验证。涉及 Agent 循环必须显式选择并添加 --run-agent-tests。
- `docs/agent-repair.md`、`developer-gui-design.md` 等现行说明存在强制预检、无 token 展示的旧要求，需要明确本次替代；历史验证记录保留且标注历史。增加中英 GUI 文案。

## 潜在风险与验证

- 高频流式快照可能挤占主线程：仅对有效内容更新，GUI 使用短定时器合并绘制，结束时停表清空；收起期间不重复绘制正文。聚焦测试生命周期与展开选择。
- 取消后排队事件可能重新打开：取消或窗口退出后拒绝流式更新，空闲兜底清理；覆盖历史重放和下一条消息重置。
- 取消推理预检后，服务拒绝图片或推理失败直接出现在正式请求阶段，保留完整诊断，不自动删图重发。用 HTTP 替身确认一条普通回答仅请求一次、图片字节不变及额度边界。
- 本机 offscreen 和 HTTP 替身不能证明真实模型、Windows 打包或游戏现场表现。

## 实施顺序

先移除自动推理预检并调整计数契约；接入脱敏的临时事件与 GUI 生命周期；更新文档 / 翻译 / 测试；执行相关普通回归及显式 Agent 替身回归。无需改 Session 格式、权限或历史数据，也无难以逆转的架构选择，因此不新增 ADR 或领域术语。


## 截图澄清后的布局修正

用户明确将原始输出和状态放到 Agent 回复顶部。影响限于 `RepairChat` 的当前轮临时状态 / 折叠行呈现和 `RepairPage` 的状态同步；删除底部独立原始输出控件，底部不再显示状态。复用聊天已有链接展开与滚动规则，纯文字转义和历史隔离保持。状态行位于本轮用户消息之后、工具 / 回答之前，旧轮次内容之前不会误插入；新聊天和历史恢复清空临时展开状态。无需改变 Agent 传输、日志、请求计数或 Session 格式。补充位置与状态更新测试，执行 GUI 相关回归和截图检查。


## 最终回答后保留生成过程：补充审查

用户将“结束即清除”改为“保留并可折叠”。`RepairChat` 必须按轮次保存已完成消息及独立展开选择，当前轮流式缓冲单独更新，避免重复拼接和续聊覆盖。`RepairPage.show_event` 在 assistant message_end 到达时提交完整内容；`reload_history` 复用已有完整 message_end 事件重建，无需更改日志或 Session 格式。回答完成的自动刷新保留当前展开选择，主动重开历史默认收起。历史读取不调用模型、不重放工具，内容按纯文字转义；取消与错误只丢弃未完成缓冲。补充完整回答、同轮多次模型消息、跨轮独立折叠、重新打开及不重复拼接检查。实现不改变 Agent 传输 / 请求额度 / 手动检查，无需新增依赖或迁移。
