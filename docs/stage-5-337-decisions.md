# #337 — 实施前决策确认

2026-11-01。开发者已确认评审并明确“开始实施337”；本地实施与验证见[实施记录](stage-5-337-implementation.md)。开发者随后明确“人工验收没有大问题，通过并关闭”，#337 已按 completed 关闭。以下保留实施前确认过程。

既有范围与版本语义见 [Stage 5 规格](stage-5-agent-workbench.md#外部知识与-git-内容的版本语义)及 [#337](https://github.com/HSLix/LixAssistantLimbusCompany/issues/337)。

## 1. 首次访问仓库的触发边界（已确认）

列目录不触发 fetch；读取仓库文件、检索其内容或查看 Git 历史时，才触发该轮对该仓库的首次自动 fetch。跨库内容检索对实际参与检索的每个仓库分别触发一次，并报告同步结果。

同轮后续访问不重复自动 fetch，仍可显式 fetch；失败不自动重试，本地资料保持可读。每次 fetch 尝试后执行 status，分别报告实际结果。仅列目录不能据此声称已检查远端更新。

## 2. 首版资料格式（已确认）

支持纯文本资料（如 Markdown、源码、JSON）的读取与内容检索，以及图片查看；图片不做 OCR。PDF / Word 等暂不支持解析的格式可以列出，但明确提示不支持解析，由开发者先转换；不能将找到文件表述为已读取其内容。

## 3. fetch 的认证、超时与取消（已确认）

仅使用开发者预先配置的非交互认证，不弹登录窗口、不等待密码输入。每次 fetch 最长等待 30 秒；认证失败或超时后执行 status，返回本地内容与失败提示，同轮不自动重试。私有仓库的认证准备由开发者在外部完成。

用户取消时终止相关等待并完成进程清理；取消不伪装成成功，也不触发自动重试。Git 操作仍须遵守既有受控参数、禁止任意外部程序执行及日志脱敏边界。

## 4. 系统 Git 依赖与不可用降级（已确认）

首版使用系统已安装的 Git，不捆绑或自动下载安装。Git 不可用时跳过 Git 操作、记录日志，本地资料的列目录、读取和检索继续可用；不增加安装或错误弹窗。

跳过不表示已检查远端或仓库已是最新；工具结果须如实保留未执行 / 不可用状态，供 Agent 正确解释来源与版本限制。

## 5. Git 辅助程序的实践边界（已确认）

正常使用开发者配置好的 Git 连接与认证；查看内容时禁用外部 diff、textconv 等非必要扩展，Agent 不得修改这些配置或指定额外命令。不引入审查所有 Git 配置的机制。

此前“仓库级执行配置一概不予采用”的宽泛建议已撤回，不作为决定；Git 正常调用连接 / 认证辅助程序，不等于获得执行参考项目的权限。受控操作、参数与路径校验，以及非交互认证、超时、取消和日志脱敏边界继续保持。

## 6. GUI 打开知识库目录与缺失时创建（补充要求）

Developer GUI 的 Agent 工作台提供“打开外部知识库文件夹”入口，Construct / Repair 均可使用。点击时若数据目录中的 knowledge 文件夹不存在，由 GUI 创建空目录再交给系统文件管理器打开；已存在则直接打开，不覆盖或清空内容。此入口不依赖已创建 Session，也不要求先发送消息。

创建仅针对固定知识库目录，不授予 Agent 创建任意目录或编辑资料的权限，不触发 fetch。目标被普通文件占用、路径越界或创建 / 打开失败时明确报错，不删除既有文件以强行创建。
