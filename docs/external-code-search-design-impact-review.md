# 外部知识库混合搜索、版本更新与 Agent 进程复用：影响审查

2026-11-05。依据[16 项已确认决定](external-code-search-decisions.md)、当前工作区源码及[保留的验证证据](external-code-search-validation.md)。本报告为实施前影响审查，不表示功能已实现、旧验收已覆盖新行为，或 Windows 已验收。工作区已有 Sharing 等并行修改，本审查按当前文件检查，不以 HEAD 替代实际状态。

## 设计变化

| 原约定 | 已确认替代目标 |
| --- | --- |
| Git fetch 仅更新对象／引用，不改工作区 | 每仓库保留可用 A，独立 B 执行 fetch／reset／建索引；全部成功才切换；失败继续 A，分别报告实际状态 |
| 单一 knowledge_search 字面检索 | 改名 knowledge_search_literal，新增 knowledge_search_hybrid；保留字面子串语义，混合检索优先英文 query |
| pi 每轮新建进程和临时目录 | pi 与 codesearch 首次需要启动、跨轮复用、宿主退出关闭；失效时按需重启，执行中退出不重放本轮 |
| Windows with-pi／without-pi | 同时构建自带 Agent 功能包与精简包；前者含 pi、codesearch、MiniLM，后者可调用用户外部资源 |
| 更新不需要整套副本预算 | 更新前按实际文件系统检查 B 及构建临时空间；空间不足向上传错，保留 A；运行中耗尽同样失败 |

保留 GUI Construct／Repair 知识库工具范围；生命周期可复用不自动授权 CLI／Runtime。首版仅搜索与读取，不接入符号影响分析、项目构建、全局 hooks、任意终端或自动下载。普通目录及 Sharing 导入历史仍可读，不纳入 Git 覆盖更新。

ADR 0034 明确禁止更新工作区，与新目标存在**已确认的设计替代关系**。应以新 ADR 记录限定更新例外，而非将旧实现改称已经满足新需求。旧 #337 与包装验收仍是历史证据，不倒改其结果。

## 已确认差距与修改范围

### 1. 文件、搜索、Git 查看与资源复制必须解析同一可用版本

证据：`src/lalc/knowledge.py:KnowledgeLibrary.read/search/git_operation` 直接访问 knowledge 工作区；`synchronize` 仅 fetch，`search` 在 os.walk 已取文件清单后才同步。新增工作区更新若原地追加，会漏新文件或访问已删除文件。`src/lalc/repair_tools.py:page_resource` 的 knowledge 复制分支直接使用 `self.knowledge.path`，承诺不 fetch；它也是版本路径的消费者，不能遗漏。

必要修改：集中解析逻辑仓库与当前可用目录，禁止各工具自行猜测 A/B；先同步参与仓库、再扫描；列表与 page_resource 的不 fetch 语义保持。结果使用仓库相对路径，不暴露内部副本作为新的任意文件读取入口。已有分页哈希、链接／junction 校验、图片原字节及未支持格式提示保持。普通资料路径不强制建索引。

### 2. A/B 发布需要最小持久状态，不做原地失败回滚

证据：验证已用独立 Git 副本、确定提交、完成索引和小 JSON 指针演示成功切换；真实索引错误及 SIGKILL 后仍能查询 A。上游只读服务不执行宿主仓库锁，因此不能让其自动监视并写入可用 A。

必要修改：宿主持有现有真实仓库 ProcessLock，独立构建 B，发布前验证文件／索引完成且目标可查询，再替换当前版本记录。服务注册及读路径必须随版本切换；处理旧服务句柄不能任由内存仍路由 A 而工具声称 B。读取携带版本身份，旧搜索结果不得在新版本读出不同正文。未完成副本不作为可用版本，启动恢复以已发布记录为准；不自动重放更新或 Agent 工具。完整断电持久性、原子文件替换及 Windows mmap 占用仍属潜在风险，需针对验证，不能根据原型扩大承诺。

多仓库逐库发布，无跨库整体事务。首次无索引失败仍允许字面与文件读取；有 A 时 B 失败则各入口继续 A，并保留更新错误。无 Git、upstream 缺失或 detached HEAD 仍不猜分支、不宣称远端最新。每轮首次内容访问同步一次及显式重试沿用；服务启动本身不等于仓库同步成功。

### 3. 磁盘预检已有可复用实现，但估算与错误传播需接入

证据：`src/lalc/file_content.py:require_disk` 已按 `st_dev` 合并同盘需求，通过 `shutil.disk_usage` 检查空闲量，并抛出带需求／可用量的 OSError；Sharing 和页面包已使用。新知识库更新没有调用该预检。

必要修改：构建前计算新增 B 的文件／Git 对象／索引副本与预计构建临时量，按其实际目标盘合并；已占用的 A 已反映在 free 中，不再把 A 当新增需求重复扣除。fetch／索引大小难以精确预测，阶段需求变更时再检查，真实复制／fetch／索引的空间错误仍需捕获。无法查询空间不得默认为充足；不要继承 Sharing 的“允许未知容量”人工放行状态来绕过此要求。不引入固定仓库大小限制或预检通过即必然成功的承诺。

错误至少包含仓库、失败阶段、可用版本和脱敏原因，磁盘不足附预计需求／可用量。`RepairTools.call` 已将异常写入工具日志并返回 isError，但 `KnowledgeLibrary.synchronize` 会捕获异常放入 sync 字段；接入必须明确让外层工具返回更新失败信息，不能因为还能读 A 就丢失失败。跨库可返回可用内容，但要明确失败仓库，不能空数组冒充零命中。不要新建第二套磁盘预算服务。

### 4. pi 复用的主要影响是事件循环与每轮配置，而非进程存活探测

证据：`src/lalc/pi_probe.py:configured_pi` 的临时目录覆盖整轮，`_rpc_session` 退出时回收进程；`agent_repair.py:AgentConversation.run` 每轮配置环境、历史和工具，CLI `run_repair` 每轮 asyncio.run；`developer_gui.py:Operation.run` 每项操作新建 asyncio.Runner。异步管道无法直接交给下一轮已更换的事件循环。

必要修改：给存活进程及传输一个明确的宿主级所有者／稳定事件循环，复用现有 Operation 的进度与取消接口，不把所有后台任务都改成新框架。每轮显式配置历史、权限、Candidate 根、工具额度、图片／传输路径与系统提示；Session 切换必须隔离，不靠原进程 env 自动变化。已验证 new_session 会重载扩展，扩展 API／ctx 换代后旧引用失效；用新回调初始化，避免手工清理 pi 全部内部状态。模型地址／密钥、provider 等无法安全热切换的连接配置变化时，可以按需丢弃旧进程后重建，不为“始终同 PID”增加复杂度；该技术方案须在接线测试验证。

启动／复用失败按既定策略报告，未发送本轮请求前可重建；发送后不自动重跑。本轮 abort 等待就绪，无法确认清理完成则丢弃进程；不能把未完成工具回调送入下一轮。保留既有版本警告、限定启动回退、认证隔离、诊断脱敏与请求额度，避免在每次复用时重开一次回退机会。

### 5. 服务退出接应用宿主，不接开发窗口

证据：`src/lalc/gui.py:GuiCoordinator.closed` 关闭 Developer GUI 后 User GUI 可以继续；`GuiCoordinator.shutdown` 最终调用 `ApplicationService.shutdown`，后者目前只处理运行线程；CLI 的 service 生命周期是独立入口。

必要修改：两进程由宿主退出统一关闭，并覆盖 CLI 正常退出、异常、GUI 退出和应用重载路径；窗口关闭不能误杀仍属于活跃宿主的进程。仅终止自己启动的实例，不凭固定端口占用杀其他进程。使用按需检查与现有超时清理，不增加保活线程、周期健康检查、无限重试或通用服务注册框架。多宿主的知识库更新仍用已有跨进程锁，专用 codesearch 注册目录／端口所有权需清晰。

### 6. codesearch 需受控接入，不能整包开放 MCP 或依赖“只读”标签

证据：保留实验已证明 repo_read_only 仍启动 TS 辅助程序；本机限制工具 PATH 后 helper 状态不可用。get_chunk 在源文件保留 mtime 时会无提示返回旧内容；index 对非独立 Git 子目录会上溯到父根。

必要修改：优先使用受控 HTTP 搜索适配，只传宿主解析的 project／group 和查询参数；不透传 endpoint、外部路径、任意服务管理请求或远端 federation。注册前验证 Git 顶层根等于获准根，并排除 knowledge 根、Sharing 保留目录、嵌套仓库及已有禁止链接／外部对象边界。codesearch 使用固定受限环境、基础版与已准备模型，不自动发现 npm／SCIP 工具链；Windows 路径必须实测，不能照搬 macOS PATH。

查询进程只读使用已完成索引，宿主显式构建更新。首版可让搜索返回版本、相对路径、位置和受控摘录，再沿用 knowledge_read 验证正文，避免为了上游有 get_chunk 就增加第二套通用读工具。查询无命中不证明文件不存在，近邻分数不是概率；工具说明写入英文 query 建议及字面搜索用途。服务错误／部分失败与真实空结果分开。

### 7. 工具重命名需要双端同步，历史记录不迁移

证据：`src/lalc/agent_policy.py:KNOWLEDGE_TOOLS`、`repair_tools.py` 方法／分发与 `pi_probe.ts` schema 都使用 knowledge_search；`tests/test_developer_session_agent.py` 包含真实 pi 的声明与调用验证。CLI 白名单从入口交集取得。

必要修改：三处同改为 literal 并增加 hybrid，更新实际工具概览／指引。历史 toolName 原样保留、不重放，不批量改写旧日志；新轮声明与授权仍来自当前代码。CLI／Runtime 不因旧 GUI 历史或生命周期复用获权。无需增加通用 MCP 客户端库，优先沿用标准库 HTTP 与现有日志结果格式。

### 8. 双包构建由资源差异扩展，不分叉应用

证据：`scripts/build_windows.py:assemble` 现有 base／with_pi 副本、pi 哈希校验及排除 pi 后的相同主体文件校验；`tests/test_windows_packaging.py` 和 `tests/test_pi_startup.py` 覆盖相关边界。

必要修改：资源清单扩展到固定版本的 pi、codesearch、MiniLM、许可声明及校验值，两包仍从同一冻结主体复制并校验；调整包名、构建参数、build-info 与打包说明。精简包保持外部资源调用，缺失 codesearch／模型只影响混合搜索，不误报完整 Agent 都不可用；缺 pi 按原 Agent 启动错误处理。模型资源从成品只读位置准备到专用缓存时也要预算目标盘，不写安装目录，不在普通使用时下载。macOS 当前是开发验证环境，不凭本轮要求新增未确认的 macOS 发行构建。

1. 记录替代 ADR；更新 CONTEXT 的只读／同步边界、Stage 5 规格、#337 当前用法、Agent 指引、pi 生命周期与 Windows 包装说明。旧验收和测试数字保持历史，不回填成功。
2. 先完成单仓库 A/B、统一路径解析、磁盘预检及错误报告，再接混合查询；覆盖 page_resource 的无 fetch 读取、列表与普通目录／Sharing 不受索引状态影响。
3. 完成宿主进程所有权与稳定传输，再接 pi 每轮配置、取消与重启；不扩展其他 Operation 的职责。
4. 最后接双包固定资源与校验，保留精简包外部调用。

普通测试重点：磁盘不足时未创建／修改 B 且 A 不变、同盘预算合并／跨盘／查询空间失败、预检后实际 ENOSPC、更新失败信息到达外层及日志、首次失败降级、跨库一成一败、Git 根上溯拒绝、链接／保留目录、全部读入口版本一致、分页变化、工具新名权限和旧日志恢复、两包资源差异与哈希。复用现有测试模式，不照搬原型作为生产实现测试。

显式 Agent 集成重点：同一实际 pi PID 跨轮、模式／入口／Session／图片／地址设置切换、额度与工具声明重置、工具中取消／进程退出不重放、替身拒绝连接后的下一轮重建、GUI 与 CLI 宿主退出清理、混合搜索错误能被 Agent 看见。新增涉及真实 pi／Agent／模型服务的测试标 agent，普通与 Agent 测试串行执行。最后单独列出 Windows 成品、真实认证与参考仓库规模验收，不用 macOS 替身代替。
