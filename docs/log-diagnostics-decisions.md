# 日志截图、Agent 日志检索与对话时区决策

2026-11-12，逐项确认后实施；下文保留决定的演进过程，后续明确修订优先。影响审查及执行证据见 [专项记录](log-diagnostics-impact-review.md)。

## 已确认：日志截图允许有损压缩

- 用户确认日志部分截图采用有损压缩；日志截图用于诊断，不作为素材获取来源。
- 素材必须通过 Agent 的素材工具或从游戏重新截取，不能依赖历史日志截图提取素材。
- 用户进一步确认：截图时机和数量保持不变，仅压缩图片。本决定不授权修改素材像素或删减日志事件。
- 用户查看同图 JPEG 85 与 WebP 85 后认为肉眼难以区分，最初选择 WebP；随后要求以同图 AVIF 成品检查替代复杂的专项实验，可用则直接作为当前方案。
- 已生成并目视检查同图 AVIF（quality=65、speed=6，原分辨率），全图及小字局部未见影响日志诊断的明显劣化，按用户授权将 AVIF 作为当前日志截图压缩方案，替代 WebP 提案。
- 样本原 PNG 936,489 字节，WebP 85 为 97,908 字节，AVIF 为 67,476 字节；本机单次 AVIF 编码约 106 ms。上述参数不是跨格式等画质声明，也不是持续截图性能或 Windows 验收结果。
- 现有 `file_content.image_preview` 经 Pillow 解码并输出 JPEG 供 Qt 显示，已在本机用该 AVIF 实测成功；Qt 未列出 AVIF 不构成该预览链路不支持 AVIF 的证据。
- 当时旧日志处理尚待讨论；最终采用旧日志保持原样，不单独扩展专项验证工具，实施时完成相关功能检查。
- 用户最终确认编码参数：AVIF quality=65、speed=8，subsampling 不显式指定，沿用编码器默认值。本机当前 Pillow 默认结果与显式 4:2:0 一致；4:4:4 对比后未被选用。此确认替代前述 speed=6 候选。
- 用户提出数小时运行的图片增长担忧；当前“截图时机和数量不变”的已接受决定尚未被替代，需要先量化增长再讨论是否另行变更保留策略。
- 随后用户提出关闭 OCR／match 自动落盘，仅保留文字日志，作为减少图片数量的具体方向；该方向替代“所有截图时机和数量均保持不变”的前提，失败场景等边界尚待确认。
- 样本 Trace 检查：Run 103 的 196 张图片中 192 张仅被 OCR／match 的 `debug_image` 引用；Run 105 的 378 张中 371 张仅被这两类动作引用。共 563/574（约 98.1%）；其余图片也被 click／drag 引用。此为引用分类，不是已执行修改后的产量验收。
- 用户修订并确认最终自动截图边界：OCR 保留自动截图；仅关闭 `observe.match_asset` 自动截图，match 报错也不自动截图，保留完整文字日志。click／drag 及显式截图保持。该决定替代前述同时关闭 OCR／match 的方向；98.1% 合并统计不能用作最终方案的准确收益。

## 已确认：外部知识库查询开关

- 用户要求在开发者面板 Agent 设置增加“允许查询外部知识库”，默认 True。
- 用户确认开发者 Agent 和运行时自动修复 Agent 都受控，每轮开始时读取设置。
- 关闭时禁止知识库列目录、读取、搜索及 Git 查询，并检查从知识库复制页面资源的旁路。独立历史记录和 Skills 不视为外部知识库。

## 已确认：Run 列表元数据

- `list_runs` 提供 Run ID、开始／结束时间、耗时、状态、入口 logical name、Manifest ID、运行来源、最终结果和失败原因；记录不足时明确未知，不根据缺失结束事件断言仍在运行。
- 用户要求来源名称使用“Agent 试运行”，替代“开发者试运行”；另一来源为用户运行，旧记录无法确认时为未知。

## 已确认：Session 工具缩略信息

- 用户要求 Agent Session 工具缩略信息更丰富，read、edit 必须显示操作文件名。
- 工具摘要显示文件／路径、Run ID、logical name 等操作对象；完整参数继续放在展开详情，摘要限制长度。
- 用户再次明确 click／drag 的自动落盘图片必须保留；仅 match 关闭自动落盘，OCR 保留。

## 已确认：日志过滤、搜索和工具描述

- 用户确认 `read_run_log` 增加 level、logical name 过滤，多个条件取交集。
- 增加关键词搜索工具：默认搜索指定 Run，可显式搜索全部保留的 Run；不区分大小写的文字子串匹配。
- 搜索返回 Run ID、事件序号及匹配原文，支持分页；Agent 可以按事件序号进一步读取前后事件。
- 用户明确要求同步相关工具描述；实施覆盖模型可见说明、参数定义和相关使用指导，不只修改宿主方法。

## 已确认：本地时区与稳定上下文

- UTC 日志格式保持；Agent 面向用户采用运行电脑系统当地时区，用户明确指定时区时优先遵循。引用日志时间先换算，跨日带日期。
- 用户确认每轮 prompt 生成时动态获取当前本地时间、时区名称与 UTC 偏移，生成后即为该轮静态快照。
- 用户明确要求上下文构建不得动态改变已缓存前缀、干扰 KV cache：易变时间信息追加在本轮新增 prompt 内，不通过刷新系统提示或重写历史消息更新时间；工具循环内不随时钟反复更新。
- 此设计约束控制应用生成的上下文；不承诺提供商实际缓存一定命中。

## 新增：User GUI 日志阅读体验

- 用户反馈滚轮一次会翻过过多内容，要求降低运行日志滚动敏感度。
- 用户要求 JSON 仍展开显示结构，但末端短数组（如坐标 `[80, 90]`）无需把括号和每个元素各占一行。
- 已检查：`run_log_gui.RunLogPage` 的正文列表使用像素滚动，未显式设置步长；`run_logs.log_text` 对动作返回值统一使用 `json.dumps(..., indent=2)`，会展开末端数组。滚轮问题的实际平台原因尚未复现，不能仅凭未设置步长认定根因。
- 用户确认固定且较小的正文滚动步长，JSON 仅将能容纳在短行内的标量数组紧凑显示，外层对象和对象数组保持展开；不更改原始日志记录。

## 新增并接受：活动轮次工作计时

- 用户要求正在思考的折叠摘要末尾增加“已工作（Working for）”，仅显示秒、分秒或时分，不增加天等时间尺度。
- 使用 GUI 单调时钟，现场本轮开始计时，工具与状态变化不重置，轮次结束／取消／清理停止；历史回放不重新启动。只更新界面，不更新 prompt 或写入高频日志。
- 旧日志不重写，仅新 Run 诊断截图采用 AVIF；不新增迁移或专项编解码实验工具。
