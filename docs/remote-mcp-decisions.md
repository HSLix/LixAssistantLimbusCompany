# 远程 MCP V1 设计确认

2026-11-15。按用户要求逐项讨论并记录决定；完成整体确认后进行影响审查，再实施。本文不表示已实现或已验收。

## 已确认

- V1 只使用和验收 Mac 上的 Codex 桌面应用，通过 Tailscale 连接 Windows LALC；CLI、Claude Code 及云端任务不属于 V1 使用与验收范围。
- LALC 提供专属 Remote MCP Workbench（远程 MCP 工作台），不要求同步外部 Agent 对话为内置 pi 对话。
- V1 只有一个持久化 MCP 工作台。断线、关闭 Codex 或重启 LALC 后保留草稿；可从用户指定的已发布 Manifest 或最新已发布 Manifest 初始化，初始化后固定来源，不随新版本发布自动更新。更换来源会替换草稿，须由本地用户明确确认。
- 每次成功取得开发控制权算一次工作台使用：先向外部 Agent 返回此前的上次使用时间，再持久保存本次使用时间。首次使用明确表示尚未使用，不伪造时间；连接探测、查看状态及持有控制权期间的后续工具调用不更新时间。
- MCP 权限组独立定义，初始权限内容与 pi Construct 相同；不是直接共用同一权限组，也不自动跟随 pi 扩权。
- MCP 服务由 LALC 本地控制开启和关闭，外部 Agent 只能使用已开启的服务，不提供远程启动、停止或重启 MCP 服务的权限。此处服务开关与 Workflow 的执行控制不同，后者另行确认。
- 服务开启与远程控制授权分开：LALC 本地点一次“允许远程控制”后，已认证的 Codex 可在空闲时取得、释放开发控制权，直到本地撤销授权；每次接手不再重复弹窗，Construct 原有人工审批仍保留。关闭 Codex 不撤销此授权。
- 网络断开或关闭 Codex 后保留开发控制权，不因超时自动释放，即使当前没有 Workflow 在运行。外部 Codex 重连后可续接，或由本地用户撤销；断线本身不终止正在执行的 Workflow。控制权保留期间继续阻止本地 pi 新任务与本地新运行，直到主动释放或本地撤销。
- 本地撤销远程授权采用简化停止流程：立即拒绝新的远程操作，向远程报告授权已撤销／停止，并停止本地正在处理的相关远程任务，复用现有取消、输入释放、日志保存及提交／回滚边界；正常清理完成后恢复本地使用，不另建复杂撤销流程。断线时不保证远程立即收到信号，重连或后续调用须能获知已撤销；协作式停止未完成前不允许新执行器并行操作游戏。
- 退出 LALC 时停止相关任务并沿用现有安全清理；重新打开后保留工作台，但 MCP 默认关闭，远程授权与开发控制权不自动恢复，须由本地重新开启、授权。
- V1 使用 LALC 生成的专用随机 Bearer Token 认证；在 Mac Codex 中配置一次，LALC 重启后仍可复用。LALC 本地可重置令牌，旧令牌立即失效。持有令牌只完成身份认证，不替代本地授权或开发控制权获取；凭据不得进入聊天、源码或操作日志。
- 网络入口采用 Tailscale Serve 的 HTTPS 转发：LALC MCP 仅监听 Windows 本机地址，Serve 在 Tailscale 私有网络提供 HTTPS 入口并管理证书，不开放公网入口。首次部署配置 Tailscale HTTPS 与本机转发，再将地址和令牌配置到 Mac Codex；Serve 转发配置不具备启动 LALC 或开启 MCP 的权限，实际服务仍由 LALC 本地开关控制。
- 开发控制权按控制会话独占，不按 Mac 设备或连接令牌独占。LALC 成功授予控制权后返回独占控制凭据，当前聊天后续操作和断线续接使用此凭据；另一聊天即使共用连接令牌也不能直接接手，须等待原控制会话释放或本地撤销。GUI 展示控制会话与取得时间，客户端自报名称不作为已验证身份；普通状态查询不暴露控制凭据。
- MCP 复用现有 `validate_and_publish`，一次完成校验与发布：失败返回结构化错误且不发布，通过后保存不可变 Manifest 并返回版本 ID，发布不改变 Default。V1 不额外增加只校验、不发布的 MCP 工具。
- MCP 试运行采用启动与结果查询分离：启动成功立即返回 Run ID，启动拒绝返回原因且不生成 Run ID。运行中的查询保持最小，只返回运行状态（运行中／已停止）及最近 5 条日志内容，日志包含 Debug，不默认返回完整 Trace 或截图；停止后可查询最终结果，详细日志及截图按需另行读取。查询结束或网络断开不取消 Workflow，停止须走显式 Stop 或本地撤销。
- 发布与启动试运行使用操作编号去重：相同编号、相同参数重试返回原操作的状态或结果，不重复执行；相同编号、不同参数拒绝。断线后可凭操作编号查询实际结果；明确再次试运行使用新编号。
- V1 远程执行控制仅提供启动、查询和停止，暂停／恢复保留在 LALC 本地；本地暂停或物理接管后，Codex 不能自行恢复游戏操作。轻量查询须如实区分运行中、已暂停、已停止，仍只附带最近 5 条日志；远程可请求停止已暂停的 Run。
- 远程持有控制权期间，本地开发功能原则上只读：不启动 pi、新运行或并行修改开发数据，保留查看、暂停／恢复、Stop、撤销与远程请求的人工审批。用户确认的辅助操作例外：允许查看 Asset、预览已有截图，在已有截图上调试模板匹配、SIFT 和 OCR；远程没有运行或工具操作时，可通过同一服务串行执行本地截图和保存素材，操作须留记录供 Codex 查询。远程忙碌或 Run 暂停仍占用环境时禁用这些截图／保存操作；素材删除、标签修改、窗口尺寸调整仍受限制。
- 远程试运行期间工作台暂停修改：Codex 仍可查询状态、读取代码和日志、查看已有截图证据及请求停止；修改 Candidate、发布、修改素材和重新截图须等 Run 结束后再进行，Run 暂停时同样限制。V1 不支持一边试运行、一边准备下一版代码。
- 主动释放仅在空闲时成功：立即交还控制权并恢复本地功能，但保留本地授权，Codex 可稍后重新取得控制权。仍有运行或工具操作时拒绝释放，须先等待完成或 Stop，并在清理完成后再释放；不引入执行未结束而控制权已交还的中间状态。
- Construct 需要人工审批的操作继续由 Windows LALC 展示并确认，包括页面安装预览及页面启停；Codex 获得等待本地确认的状态和最终结果，不可用普通聊天中的确认替代专用审批。普通开发对话继续在 Mac Codex 完成。
- 审查后用户明确 MCP 服务开关放在 Developer GUI，采用现有侧栏中的独立“远程 MCP”页，集中服务、连接授权、工作台和近期操作管理。

- 用户要求先审查、查看审查结果后再决定实现；先前“审查后直接实现”的提议不构成当前实施授权。产品实现尚未开始。
- 随后用户明确“开始实现”，授权按已确认范围实施；上条保留为审查阶段的历史边界，不代表目前仍禁止实施。
- 审查后的保守实现口径：MCP 素材归档统一在 Windows 确认，不接受模型自报明确用户要求而跳过；令牌重置一并撤销；换来源只替换 Candidate／基线，保留页面草稿并在本地确认中列明；人工反馈和页面审批通过异步操作查询等待状态。全局历史、知识库和 Manifest 查询开关在接手时固定，仍由服务端强制执行，不把 pi 模型参数或请求额度带入 MCP。

## 整体方案（已授权实施）

以下合并用户初始草案和上述逐项决定，已完成影响审查并获用户授权实施；审查后的保守口径见前节，实现及验证以独立实施记录为准。

- MCP 权限内容以确认时 pi GUI Construct 为基准，独立定义，后续不因 pi 权限组变化自动扩权。开发范围为专属 Candidate 和页面草稿、现有受控 Asset 操作、Skills 与知识库参考、Manifest 和授权历史查询；复用原有参数校验、人工审批和路径边界，不提供任意系统命令、任意文件修改或 Trusted Action 修改权限。
- 外部 Agent 可按需发现、读取 LALC 开发指导与受控参考内容，不要求跨设备文件同步或复制 Codex 对话；实际工具映射及 pi 专有接入逻辑的替代由影响审查核对。
- Developer GUI 增加简洁远程 MCP 区域，显示本地服务开关、连接地址与凭据管理入口、远程授权、当前控制会话、工作台来源及上次使用时间、Runner 状态和近期操作；不新增聊天终端。
- 本地记录 MCP 工具调用、参数及结果，关联控制会话、操作编号、工作台、发布版本和 Run；日志不记录认证／控制凭据，不假称包含外部 Agent 的完整对话或推理。
- V1 不接管 Stage 6 Runtime Recovery，不开放运行中 Recheck，不支持多 Agent 并发、多个 MCP 工作区、公网服务、远程桌面或跨设备文件同步系统。
- 工具权限不是 Python 沙箱，Validate 不证明 Workflow 安全；必须在本地授权处明确这一执行边界。
- 验收覆盖 Mac Codex → Windows LALC 的读取参考、修改、发布、试运行、读取结果和继续修复闭环；同时覆盖互斥与拒绝、本地辅助调试、暂停／停止、撤销、断线续接、操作去重、应用重启和日志关联。本地替代测试与真实跨设备／Windows／游戏验收分别报告。
- 整体确认后进行影响审查，再实施；审查若发现须改变已确认边界，返回讨论。

## 当前检查依据

- `src/lalc/agent_policy.py`：内置权限由模式与入口取交集，Construct 包含页面工具及人工反馈；新增 MCP 权限须单独建模，不能靠历史或 Prompt 授权。
- `src/lalc/developer_session.py:DeveloperSession.create`：已有 Session 以独立 Candidate 和固定来源基线隔离草稿，但目前仍是内置 Agent 对话模型。
- `src/lalc/application.py:ApplicationService.activity/start/_begin_run`：共享服务活动和系统用户级游戏锁可复用，但远程控制权的生命周期需另行明确。
- `src/lalc/repair_tools.py:RepairTools.publish/trial_run`：现有工具为 `validate_and_publish`；试运行工具等待 Run 结束，取消工具会停止 Run，不能直接当作符合断线保活要求的远程接口。
- 本机 `codex mcp add --help` 已确认支持 Streamable HTTP 地址与 Bearer Token 环境变量配置；[官方 MCP 文档](https://developers.openai.com/codex/mcp/)描述相应配置能力。尚未修改客户端配置或验证跨设备连接。
