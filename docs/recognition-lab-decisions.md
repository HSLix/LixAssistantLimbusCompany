# 识别调试页合并：设计决定

2026-11-14，主要交互已逐项确认；开发者确认影响审查并回复“开始实现”，已授权实施。

## 已接受

- 开发者面板的模板匹配与 OCR 页面合并为一个识别调试页。
- 采用方案 A：顶部标签切换识别方式，共用截图画布；展示当前方式对应的操作区与结果。
- 模板匹配与 OCR 共用同一张固定截图，不再各自持有独立截图；切换方式不重新截图。
- 选区不跨识别方式共享；切换方式后恢复该方式自己的选区。重新截图成功后，所有方式的选区重置为全图。
- 截图后，所有方式均不自动执行。模板匹配提供专门的“全图匹配”按钮，OCR 提供专门的“全图识别”按钮。
- 拖动框选结束后，当前方式自动处理该选区：模板匹配运行选区匹配，OCR 运行选区识别；开始拖动及拖动过程中不执行。
- 点击“全图匹配”或“全图识别”时，清除当前方式的选区并立即处理全图；不改变其他方式记住的选区。
- 各方式分别保留参数、选区和结果；切换标签恢复对应状态，不自动执行。
- 重新截图成功后，所有方式的选区和结果全部清除；保留各方式参数及模板素材选择。
- 修改模板选择或匹配参数后，清除模板匹配的旧结果，不自动执行，也不改变其他方式的状态。
- 保留“匹配当前选区”按钮，供调整参数后手动重试；没有选区时使用“全图匹配”。
- 重新截图失败时，完整保留旧截图、各方式选区和结果，并明确提示失败；只有新截图成功后才替换截图并执行重置。
- 共享截图只限合并后的识别调试页；原有截图／素材保存页继续独立，不因调试页截图而改变素材保存预览。
- 后续可通过新增标签及对应操作区／执行逻辑接入其他识别方式；本次不增加动态插件框架。
- 完成设计讨论和影响审查，经开发者确认影响后再实施。

## 实施审查约束

- 保留现有后台活动互斥、错误提示、原像素坐标换算及只读调试边界。
- 后续方式的具体接入结构在影响审查中提出，不预先引入动态插件或注册框架。
