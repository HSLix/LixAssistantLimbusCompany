# Agent 会话标题与管理交互确认

2026-11-11。本轮按 grill-with-docs 逐项确认，完成影响审查后再实施；下列已确认项不代表已实现。

本地实施及针对性验证已完成，结果与验收边界见[影响审查](session-management-impact-review.md#实施与验证)。

## 已确认

- 会话标题由首条用户消息初始化，后续用户消息不自动改名；提供手动重命名。
- 历史会话项鼠标悬停时，在右侧显示可识别的子菜单入口，菜单提供“重命名”和“删除”。
- 重命名使用子弹窗，提供“取消”和“保存”。删除使用确认弹窗，强调删除后不可恢复。
- 删除为彻底删除：对话、附件、会话私有的未发布工作流 Candidate 与页面草稿一并删除，并清除对应历史检索记录。已发布 Manifest、已安装页面及共享 Asset 不随会话删除。用户已选择此范围，而非仅隐藏列表项。
- 运行、试跑、等待人工反馈及取消清理期间，统一禁用会话子设置入口。
- 删除当前打开的会话后回到空白“新建聊天”，不自动选择其他历史会话，也不立即创建新的持久化会话。
- 重命名弹窗预填当前标题，单行输入，按钮为“取消”和“保存”；保存时去掉首尾空白，空标题禁用保存。允许重名，完整名称持久保存，列表长标题省略且悬停可见完整名称；后续消息不覆盖人工名称。

## 最终确认

- 用户已确认完整方案并授权影响审查后直接实施。旧会话未手动改名时继续从首条实际用户消息提取标题，无需批量重写历史。

## 源码检查

- `RepairPage.show_event` 对每个 `workbench_session` 事件覆盖标题缓存，导致后续输入改变当前标题；`saved_title` 重开历史时按首条用户消息生成标题。
- `DeveloperSession` 以稳定 UUID 关联私有 Candidate、固定基线及日志，页面草稿也存于该会话目录。标题应是展示属性，不改变会话身份和来源。
- 历史检索有独立索引；彻底删除需同步处理索引和会话存储，不能只删除列表项。
