# User GUI P0 布局改进讨论

2026-10-28：grill-with-docs 与 design-impact-review 已完成，用户确认审查结论并授权按文档、配置/启动、界面、回归的顺序实施。本文件只记录逐项确认的决策；用户提供的完整建议稿中其他内容仍为提案。

## 已确认范围

- 本轮仅优化 User GUI 的 P0 信息层级与布局，继续使用现有 QFluentWidgets，不重写 GUI 或执行服务。
- P1 尚未实现的内容记录为 Stage 6 之后的 TODO；已经实现的动态任务循环列表、Manifest 选择、持久通知和外置业务页导航继续保留，不因优先级调整撤回功能。
- P2 的复杂展开动画、主题编辑器、自定义阴影、完整通知中心、可拖拽面板及过度精细的自适应布局忽略，不纳入实现或后续承诺。
- 首页以本轮用户附件为布局参考：左侧 Execution 卡片内按 Manifest、Task Repetitions、主要运行按钮组织；右侧保留 Announcements、Disclaimer、Version & Update 三张占位卡，明确标注尚未接入，不联网、不编造公告/声明/版本信息；Update 禁用。不将参考图说明文字当作已接入数据。
- 首页补充紧凑的 User Agent 启用状态；点击跳转 General Settings 的 Agent 区域。不能只打开通用设置而没有定位到对应区域。
- 任务列表占用 Dashboard 左侧其余控件之外的剩余空间，不设置固定高度或固定可见行数上限；保留常驻垂直滚动条，Start Plan 放在列表下方。此项替代此前限制任务列表高度的方向，不采用最多显示约 5 行的建议。
- 任务列表空状态只区分“请先选择 Manifest。”和“当前 Manifest 与已加载的配置页没有匹配任务。”两种。Manifest 加载失败应显示错误弹窗，不作为第三种列表空状态；弹窗复用既有错误展示能力。这里的“配置页”指既有 Business Settings Page，不新增页面类型。
- 第二张附件作为 General Settings 的视觉参考：使用标题、简短说明、功能分组卡片以及开关/折叠层级。参考图中的保存按钮、Mirrorchan API 实际配置、自动启动 Developer 等新增操作仍未接受，不因出现在图中自动进入本轮范围。保留既有即时保存与重载的区别。
- Agent 配置完整性按当前选用的 provider 判断：llama.cpp 需要有效服务地址和模型 ID，API Key 可选；DeepSeek 使用既有地址/固定模型约束并需要已保存的凭据。默认值计入有效配置；缺少必填项显示“待配置”。建议的调优参数不作为必填项，不因未手动填写而判为待配置。
- 启用与配置完整性分开：允许“已启用 · 待配置”，必填项齐全显示“已启用 · 已配置”；已配置不代表已验证连接。首页同步显示对应状态；状态判断不自动请求模型。Agent 区只保留一处运行时自动修复尚未实现的说明。
- User Agent 关闭时，隐藏的 Agent 配置缺项或无效均不阻止普通任务启动；保留原参数与密钥，重新开启后显示对应配置状态。业务页提交、校验及其他启动条件继续有效；不能仅隐藏表单而保留会阻断启动的 Agent 提交路径。
- User Agent 开启时，必须按当前选用 provider 的既定必填规则配置完整，才允许启动普通任务；“已启用 · 待配置”可以作为设置状态存在，但必须阻止任务启动。用户可关闭 User Agent 或补全配置后启动。配置完整性仍只在本地判断，不要求连接测试通过，不自动联网；本轮即落实此启动条件，不延后到 Stage 6。
- “已启用 · 待配置”时禁用 Start Plan，并在按钮附近显示“请补全 Agent 配置或关闭 User Agent”；点击首页 Agent 状态仍跳转 General Settings 并定位 Agent 区。启动入口保留相同的配置完整性校验，不能只依赖按钮禁用。
- Agent 字段分组：基础配置包含 Provider、服务地址、模型、API Key 设置入口、凭据状态和清除密钥；Advanced Settings 默认收起，包含请求上限、思考开关与强度、单次输出上限。测试连接、检查模型加载状态及简短结果放在基础配置下方。沿用各 provider 原有字段可见性与固定值约束，不因分组新增可配置能力。
- User GUI 不设置 Diagnostics/诊断区；错误统一使用错误弹窗，包括 Agent 连接/模型检查失败。弹窗先显示简短错误，错误详情默认折叠，由用户手动展开；复用既有错误详情、复制与脱敏能力，保留底层日志记录。此决定替代此前 Diagnostics 默认收起、检查失败自动展开及不自动弹窗的规则。已有其他日志入口继续保留，不新增诊断面板或错误历史界面；检查状态仍不得将旧配置的结果标为当前有效。
- General Settings 不设表单或卡片最大宽度；卡片随窗口可用宽度伸缩，保留统一边距。不采用此前限制表单宽度的方向或 960 最大宽度建议。
- User GUI 的 Agent API Key 不使用常驻输入框，改由“设置 API KEY”按钮触发输入弹窗；使用密码输入，不回显旧密钥。点击“确认”立即保存，成功后关闭；空输入不能确认；取消不修改；保存失败保留弹窗和输入并显示错误，允许重试。保留凭据状态显示和独立的“清除 API Key”操作；不自动扩展到 Developer GUI。
- Agent 文本配置允许保存无效内容，不因地址等内容格式无效拒绝保存，不新增智能纠正、复杂草稿或回退机制；实际使用时的错误使用统一报错弹窗。保存与使用校验分开，既定的本地配置完整性状态及启用时启动门槛继续保留。文件写入或凭据存储失败仍属于实际保存失败，不能显示保存成功。读取配置不能因已保存的无效文本导致设置页无法打开或无法修正。

## 保留的既有边界

即时保存、参数及凭据保留、每个 provider 一套共享配置、两侧独立选用、Developer 打开期间单一编辑入口、活动快照、重载前保存及清理继续以既有接受规格为准；建议稿中的可选保存按钮等不自动替代已确认行为。

Developer GUI 打开期间，User GUI 的整个 Agent 区禁用，包含启用开关、基础配置、Advanced 和连接检查；不保留区内可操作控件。区域外仅显示“请在 Developer GUI 中修改”，不新增切换入口。Agent 关闭时仍隐藏详细配置；无关设置、开发者入口和其他日志入口不受影响。Developer 关闭并完成既有保存交接后，User Agent 区恢复编辑。
