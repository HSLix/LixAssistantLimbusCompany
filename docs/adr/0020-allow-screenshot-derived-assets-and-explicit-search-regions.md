# Allow screenshot-derived Asset additions and explicit search regions

ADR 0025 moves the runtime recovery, supervised trial, and Agent Asset creation scope described here to Stage 3.5. Current Stage 3 is independent single-Component repair; these runtime contracts are not its prerequisites.

Existing Manifest and Asset files must not be modified, overwritten, renamed, or deleted by the Agent. Agent repairs create new Asset files and a new complete candidate Manifest; candidate mappings may reference different Asset files without editing existing files. Human management and modification of existing Manifest and Asset files may be provided by a future GUI; that capability and its reference/hash handling are deferred and are not implemented in this version. For Manifests and Assets, this is an Agent permission boundary, not a permanent prohibition on human edits.

This restriction also applies to Agent-generated code and executor operations performed on the Agent's behalf: neither may overwrite existing Manifest or Asset files. Adapting a template means saving a new Asset file and publishing a new complete Manifest with updated path/hash mappings; existing files and their recorded mappings remain unchanged. The possibility that an Agent edits an old image and invalidates an old Manifest's hash is outside the permitted repair behavior, not a case the repair path should support. Human edits through a future GUI remain a separate deferred feature.

A valid detection with no qualifying target returns an ordinary not-found result. The Step decides whether absence is expected or requires waiting or interruption. Technical failures retain the original traceback and exception chain when propagated; they never masquerade as target absence. This replaces the earlier execution contract's unconditional interruption on a below-threshold match.

Template detection returns every qualifying target, sorted by descending score and then stable position, or an empty list when nothing qualifies. After filtering by the match-score threshold, non-maximum suppression (NMS) defaults to enabled with an IoU threshold of `0.5`: candidates are considered in that stable order, and a candidate is suppressed when its IoU with an already selected box exceeds the threshold. Both NMS enablement and its IoU threshold are explicit caller parameters; disabling NMS returns all score-qualified candidates. Cross-language template selection remains a separate decision: choose the highest-scoring qualifying language template, breaking exact score ties by stable relative-path order, then return that template's detections within the requested search region. Cross-language matching never automatically adds a mapping for the running language, including after Step success; mapping changes require an explicit complete candidate Manifest through ordinary validation and selection.

When the Agent requests a template crop with a region, the executor captures the current Target Window anew, crops that fresh image, writes a new PNG atomically, computes its complete hash, and stores the new Asset directly in the globally shared image file store. It returns an inspectable cropped-image reference so the future Agent can check the image before preparing repair code and a complete candidate Manifest. The recorded provenance identifies the fresh observation actually cropped and its crop region. Saved screenshot files are not crop sources; the request is not bound to a prior observation ID and is not rejected merely because an earlier observation was replaced. External image import and generated images are outside this scope. Existing Asset files are never overwritten, renamed, or deleted by the Agent; the dedicated Asset Library published alongside a complete candidate Manifest may reference the new file while retained older Manifests keep their original references. Runtime review, formal trial, and permanent approval continue to apply to the complete proposal. ADR 0021 removes Batch tracking and defers all resource cleanup to a future module; neither approval nor rejection deletes files. This replaces the blanket exclusion of Asset additions in ADRs 0003, 0009, 0011, 0013, 0014, 0015, and 0018; Trusted Actions and Recovery Rules remain outside Agent modification scope. The Stage 2 implementation supplies the deterministic Asset path without implementing a model provider.

Recognition accepts an in-memory screenshot and an explicit optional search region, defaulting to the full client area. Detection results use full client-area coordinates even when recognition processes a crop. Template matching is implemented first; OCR and custom-model detection remain TODOs. The Asset Usage Index is independent mutable metadata rather than an execution log: each non-empty matching result updates its time, running and source languages, complete hash, all returned detections with scores and normalized regions (after NMS when enabled), and Run/Trace/observation references. This requires neither explicit usage acknowledgement nor eventual Step success; empty results do not update the Index. The Index supports developer and future Agent inspection. Detailed evidence belongs to the Run Log Bundle; an observation reference does not imply that screenshot pixels were saved, and references may outlive retained evidence. History never changes, narrows, or expands a detection's search region. This replaces the historical-region search optimization in ADR 0009.
