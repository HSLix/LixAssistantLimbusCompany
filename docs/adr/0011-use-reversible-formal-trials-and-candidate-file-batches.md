# Use reversible formal trials and top-level candidate file batches

First-version runtime maintenance may propose a complete Manifest changing Steps, Task Workflows, and Subworkflows together; Trusted Actions, Recovery Rules, and Assets are outside this Agent modification scope. After complete validation assigns the changed Components immutable identities, selection is legal only when the executor can immediately arrange the paused current Step's compatible fresh call. The first call supplies behavioral evidence: success commits the whole selected Manifest for later calls, while failure leaves execution paused for the Agent to choose any retained attempt Manifest ID as its next modification base or to end execution. Every complete Manifest actually used for an attempt is durably retained by Manifest ID, and repeated attempts selecting the same Manifest reuse that ID while Trace distinguishes attempts. There is no automatic rollback or per-change trial cycle. User Cancellation ends the Top-level Execution without changing its last selected Manifest. Runtime permission for the current execution is separate from permanent post-execution publication.

One Top-level Execution creates at most one Candidate File Batch containing only Component source files it actually created. Manifest mappings decide current runtime availability; the Batch owns final file disposition. Attempted Manifests remain available by ID during repair. If execution ends with a current Working Manifest ID that has not already received permanent approval, only that current Working Manifest is offered for post-execution approval; returning to the Base Manifest or another approved ID skips repeated approval, and intermediate attempts are not reviewed one by one. The review records final Task verification, including failure, and trial evidence without using success as an automatic gate, as decided by ADR 0016. Approval remains whole-Manifest with no partial file or Component approval. Cleanup removes only Batch files unreferenced by a retained Manifest or Capability Proposal. Runtime selection changes neither permanent approval nor the Default Manifest.
