# Use reversible formal trials and top-level candidate file batches

First-version runtime maintenance may generate a formal candidate replacement of the current paused Step with optional related Assets, or may update only Asset files and mappings used by the unchanged Step. Asset-only repair creates no replacement Step identity. After complete validation assigns all required immutable identities and hashes, a candidate Working Manifest may be selected only when the executor can immediately arrange the resulting current Step's legal formal call. The first formal call supplies behavioral evidence: durable success commits the switch, while failure restores the pre-switch Working Manifest only when execution will continue to another Agent Turn. User Cancellation instead ends the Top-level Execution without rolling back an already selected candidate, because no further Component may execute and the selected state supplies the Capability Proposal. A failed or uncertain required rollback is terminal until the pre-switch capability snapshot is restored. No trial ID, candidate state machine, or Working Manifest version chain is stored.

One Top-level Execution creates at most one Candidate File Batch containing only Component source and Asset files it actually created. Working Manifest mappings decide current runtime availability; the Batch owns final file disposition. Runtime confirmation and successful trial affect only that execution's Working Manifest. Retaining work for review retains the entire closed Batch. After the Top-level Execution ends, the system may build one complete Capability Proposal from either the successfully trialled Working Manifest or a structurally valid unselected candidate retained when execution terminated. Its permanent review records whether a successful formal trial occurred but does not use that fact as a gate, as decided by ADR 0016. Approval remains whole-Manifest with no partial file or Component approval. Approval or rejection then removes only Batch files unreferenced by any retained Component Manifest, durable Working Manifest, rollback copy, or retained Capability Proposal. At most one Capability Proposal and Batch may remain pending globally; deterministic execution may continue from the active saved Manifest with Agent assistance disabled.
