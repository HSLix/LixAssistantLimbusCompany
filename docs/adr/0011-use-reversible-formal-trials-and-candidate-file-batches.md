# Use formal trials and retain immutable proposal files

ADR 0021 replaces the original file-ownership and cleanup design: files are retained directly in their normal stores, review records approval or rejection, and resource maintenance is deferred.

ADR 0020 supersedes only the blanket exclusion of Asset additions below: new templates may be cropped from real game screenshots and proposed through the complete Manifest review path. Existing Asset files remain immutable.

First-version runtime maintenance may propose a complete Manifest changing Steps, Task Workflows, and Subworkflows together; Trusted Actions and Recovery Rules are outside this Agent modification scope. The Agent may propose new template Assets cropped by the executor from a fresh Target Window screenshot taken for that crop request (ADR 0020); it cannot overwrite, rename, or delete existing Asset files. After complete validation assigns the changed Components immutable identities, selection is legal only when the executor can immediately arrange the paused current Step's compatible fresh call. The first call supplies behavioral evidence: success commits the whole selected Manifest for later calls, while failure leaves execution paused for the Agent to choose any retained attempt Manifest ID as its next modification base or to end execution. Every complete Manifest actually used for an attempt is durably retained by Manifest ID, and repeated attempts selecting the same Manifest reuse that ID while Trace distinguishes attempts. There is no automatic rollback or per-change trial cycle. User Cancellation ends the Top-level Execution without changing its last selected Manifest. Runtime permission for the current execution is separate from permanent post-execution publication.

Each new immutable source file, screenshot-derived Asset, and complete Manifest is saved directly in its normal store. Manifest mappings decide current runtime availability; execution and review never delete these files. Attempted Manifests remain available by ID during repair. If execution ends with a current Working Manifest ID that has not already received permanent approval, only that current Working Manifest is offered for post-execution approval; returning to the Base Manifest or another approved ID skips repeated approval, and intermediate attempts are not reviewed one by one. The review records final Task verification, including failure, and trial evidence without using success as an automatic gate, as decided by ADR 0016. Approval remains whole-Manifest with no partial file or Component approval. Approval and rejection retain all attempted Manifests and created files; reference scanning and deletion belong to a future maintenance module. Runtime selection changes neither permanent approval nor the Default Manifest.
