# Include Capability Expansion in Stage 3

Stage 3 includes Capability Expansion as a separate user-initiated activity. The Agent first reuses registered Python Workflows and Components, then may generate an immutable Python Temporary Action Plan and execute it directly through the Adapter under Supervised or warned Unattended Operation. The plan is not a Component and never enters the Working Manifest. Successful verified logic may be reorganized into candidate Components and a Capability Proposal, but it does not become a formal capability until human approval creates a new active Component Manifest.

This provides goal-directed tool use and capability learning while preserving the model-free guarantee for supported Task Workflows and the human approval boundary for permanent capabilities. Temporary generated code may run before approval but does not itself alter the Working Manifest; only separately organized candidate Components do so, and they cannot automatically promote themselves or mutate a saved Manifest.
