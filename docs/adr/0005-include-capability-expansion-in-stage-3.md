# Include Capability Expansion in Stage 3

Stage 3 includes Capability Expansion as a separate user-initiated activity. The Agent first reuses registered Python Workflows and Components, then may generate an immutable Python Temporary Action Plan and execute it directly through the Adapter under Supervised or warned Unattended Operation. The plan is not a Component and never enters the Working Manifest. The Agent may instead generate a formal candidate Component directly; neither path is a prerequisite for the other. A candidate does not become a formal saved capability until a legal formal trial supplies evidence and human approval creates a new active Component Manifest.

This provides goal-directed tool use and capability learning while preserving the model-free guarantee for supported Task Workflows and the human approval boundary for permanent capabilities. Temporary generated code may run before approval but does not itself alter the Working Manifest; only separately organized candidate Components do so, and they cannot automatically promote themselves or mutate a saved Manifest.
