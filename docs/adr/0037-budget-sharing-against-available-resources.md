# Budget Sharing against available resources instead of fixed admission ceilings

Sharing import/export and Agent page resources have no fixed object-count, file-count, byte-size or image-pixel admission ceilings. The previous constants were implementation choices without measured business justification. Use current disk and memory estimates, streaming file snapshots/copies, paginated text and on-demand image previews instead; chunk and preview sizes remain processing units. Native ZIP/JSON/Python parsers still need memory and may explicitly fail when current resources are insufficient. Existing path, hash, conflict and authority checks remain.

ZIP index and declared sizes are checked before payload extraction; budget staging and final copies per volume, require explicit human continuation when disk capacity cannot be determined, and report real write failures. A cancellable Worker prepares and validates private staging once. Review and per-object commit use those fixed files, not the original archive, with final staging integrity checks. Startup cleanup is confined to the managed staging area and skips locked live imports. This refines ADR 0036 without changing its object selection, replacement or optional human page Review rules. See the [impact review](../sharing-resource-impact-review.md) and [current contract](../sharing.md).

2026-11-09 refinement: export selection goes directly to the ZIP save dialog, without a file-review step. Working snapshots and pending output files use ordinary creation with inherited parent permissions, retaining cleanup, integrity checks, locks and rollback. Import Page Review is unchanged.
