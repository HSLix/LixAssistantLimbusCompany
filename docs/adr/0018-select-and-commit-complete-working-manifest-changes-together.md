# Select and commit complete Working Manifest changes together

2026-11-11 局部替代：恢复入口不再限 Step，允许新增／修改 Manifest Recovery Rule，不强制旧新调用约定一致，取消执行前人工批准；完整不可变版本选择与失败不回滚保留。Plan 正常结束后可按 User 的“运行成功后自动使用修复版本”设置更新 Default，不要求所有 Task 最终成功；取消／Plan 中断不切换，直接 Component Run 仍要求成功。 见 [ADR 0040](0040-share-run-state-and-reuse-agent-sessions-for-runtime-repair.md)。下文保留原决定，不代表新设计已实现。

A repair may produce a complete candidate Manifest changing Steps, Task Workflows, and Subworkflows together; Trusted Actions and Recovery Rules are outside this Agent modification scope. The Agent may propose new template Assets cropped by the executor from a fresh Target Window screenshot taken for that crop request (ADR 0020); it cannot overwrite, rename, or delete existing Asset files. Its contents must pass complete validation, and selection is legal only when the paused current Step can be invoked immediately and compatibly. After supervised permission for this execution, the executor atomically selects the whole candidate for that fresh Step call; changed Components use the ordinary execution path. A compatible return commits the whole selection, so later calls resolve every selected change. A later Step failure is a new interruption at that Step and does not roll back the committed Manifest. Every complete Manifest actually used for an attempt is persisted with a Manifest ID, including the original and intermediate selections. Trying an existing Manifest again uses its existing ID and records a separate attempt in Trace. If the initial trial fails, execution remains paused without automatic rollback; an Agent may choose any persisted attempt as the basis for another repair or end the execution. Intermediate attempts remain as history after execution; only the current Working Manifest is offered for permanent approval, and only when its ID has not already received that approval. After approval, a separate choice determines whether to set the approved current Working Manifest as Default. Any saved ID may also be set as Default independently; explicit selection requires no additional confirmation, regardless of permanent approval status. This supersedes the current-Step-only candidate-content restriction, automatic-rollback rule, and no-history rule in earlier contracts. Recovery still resumes through the paused current Step, with cross-Workflow continuation deferred until a real case shows why that boundary cannot repair the task.
