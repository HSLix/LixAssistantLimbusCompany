2026-11-01，grill-with-docs 讨论记录；影响审查见[专项记录](agent-raw-output-impact-review.md)，本地实施完成，验证和限制见[实施记录](agent-raw-output-implementation.md)。

## 生成过程保留（最新确认）

2026-11-02 布局补充：展开的原始输出与工具详情受聊天区可用宽度约束，随窗口缩放自动换行，连续无空格长字符串也不能撑宽聊天页面；保留完整文字、原有换行和缩进，不采用固定宽度。

最终回答后保留该轮完整生成过程，可继续展开 / 收起。每轮独立，续聊不会覆盖旧轮次；默认收起，当前轮用户已经展开的选择在回答完成后保持。重新打开聊天时，从已有完整模型消息恢复，默认收起。不新增逐片持久化，不修改模型上下文。取消 / 错误只清除尚未完成的流式缓冲，已经完成的消息保留。

此项替代下文初版“消息结束清空、不恢复进历史”的规则；内联位置、状态标题和取消强制推理预检的决定保持。

## 初版已确认（保留规则已被上文替代）

- 原始输出包括模型文字、接口实际提供的 thinking，以及生成中的工具名称和参数；不展示底层通信报文，也不推断未提供的 thinking。
- 每条模型消息首次收到内容时显示临时区，默认收起；用户展开后，本条消息内保持其选择。
- 模型消息结束立即移除并清空临时区，再呈现正式工具卡片或最终回答。后续模型消息重新默认收起。
- 取消、报错或轮次结束清空；格式纠正重试不得残留旧内容。临时区不恢复进聊天历史。

## 布局纠正（已确认）

用户以截图澄清：折叠原始输出与状态应放在 Agent 回复顶部，而非输入框上方独立区域。当前采用聊天记录内的状态行，紧接本轮用户消息、位于该轮工具和最终回答之前；状态文字作为折叠标题，默认收起。消息结束仍清除原始内容，完成 / 错误等状态保留在同一位置。此项替代首版布局，推理预检决定与事件生命周期保持。

## 后续已确认

- 取消每条用户消息前的强制连接 / 图片推理预检；保留 GUI 设置页已有手动检查。正式请求直接开始，格式纠正继续计入本轮额度。

## 实施前检查的事实

- `agent_repair.py` 的预检与正式请求循环均直接跳过 `message_update`。
- `RepairLog.record()` 同时承担落盘和 GUI 事件通知，流式展示需要区分临时通知与持久事件，避免逐次保存完整消息快照。
- `RepairPage.show_event()` 处理现有正式工具事件，`RepairChat` 保留历史呈现与工具展开行为。
