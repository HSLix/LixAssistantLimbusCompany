# Session 模型连接重试影响审查

2026-11-20

## 已确认决定

- Developer GUI、CLI 和 Runtime Repair 使用相同的轮内重试策略。覆盖每轮的 `GET /models` 元数据查询以及 pi 推理和摘要请求建立连接的阶段。Settings 的手动连接和模型检查仍为单次诊断。
- 连接超时和 DNS 解析失败（`EAI_AGAIN`、`ENOTFOUND` 或 Python 对应错误）可重试。连接被拒绝直接报错。附件中的 `SSL: UNEXPECTED_EOF_WHILE_READING` 属于 TLS 提前断开，按连接失败留证。HTTP 错误、证书错误和推理响应流中断也直接报错。
- 每个请求首次失败后最多重试 999 次，失败后等待 1 秒。取消结束当前轮的重试。重试沿用一次请求额度和同一轮上下文，保留已执行的工具结果。
- 每次重试及连接恢复进入 Agent Interaction Log。工作台实时显示进度，在对应轮次的历史时间线保留每个请求的最近状态。CLI 在标准错误流显示重试事件。Runtime Repair 结束后可在同一 Session 的工作台历史查看。

## 确认的差距及处理

| 入口 | 改动前行为与影响 | 实施点 |
| --- | --- | --- |
| 轮初模型列表 | 附件中的失败来自 `configured_pi → _models`。它会在 pi 启动前结束本轮，与已取消的额外推理预检是两次不同性质的操作。原错误摘要合并了超时与其他连接故障。 | `pi_probe.py` 按底层异常分类。Session 在可取消的等待中重试，Settings 按原调用路径执行一次。 |
| 推理与摘要 | `diagnosticFetch` 留存连接与响应流错误后立即抛出。若在宿主重新提交整轮，已完成的工具可能被再次调用。 | `pi_probe.ts` 在同一个模型请求的 fetch 内重试，pi 原生重试仍关闭。已有响应流中断只留证。摘要请求沿用独立编号，宿主在摘要请求期间等待其结算。 |
| 聊天及历史 | 交互日志已经存储结构化事件，工作台可复用同一入口实时呈现及回放。原有聊天只显示本轮结束的错误。 | `RepairLog.record` 落盘和脱敏。工作台按轮次、阶段、请求号更新对应进度。现有 Session 直接读取，无需迁移。 |

## 验收边界

- 999 次重试最多产生 999 秒的重试间隔，实际耗时还包括单次连接尝试。长时间不可用时，当前轮会等待或由操作者取消。
- 普通定向回归 250 通过、1 跳过，覆盖模型列表错误分类、重试、聊天实时显示及历史回放。
- 单独运行真实 pi 与本机 HTTP 替身的定向集成回归，21 通过、59 未选中。覆盖注入故障后的恢复、缩短上限后的耗尽、取消、连接被拒绝、响应流错误和请求额度，并回归摘要及 Runtime Repair。Windows 成品和真实模型服务仍待验收。
