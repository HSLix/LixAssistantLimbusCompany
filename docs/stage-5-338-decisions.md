# #338 — 实施前决策确认

2026-11-01。下列关键决定已逐项确认，开发者确认[影响审查](stage-5-338-design-impact-review.md)后明确“开始实现”。本地实施及验证见[实施记录](stage-5-338-implementation.md)；开发者验收确认后才关闭 issue。既有范围见 [#338](https://github.com/HSLix/LixAssistantLimbusCompany/issues/338) 与 [Stage 5 规格](stage-5-agent-workbench.md#请求人工答复或操作并等待反馈)。

## 1. 空答复确认（已确认）

Confirm 允许输入为空，返回明确的“已确认、答复为空”，与 Skip / 关闭 / Esc 返回的“已跳过”区分。用户可在完成所请求的游戏操作后直接确认，无须为提交而填写文字。

确认仅是人的答复或操作反馈，不证明目标状态已达成；Agent 按需要重新观察。空答复不增加授权，不替代页面安装等专门确认，也不隐式解除人工暂停。

## 2. 人工等待不设自动超时（已确认）

等待直到 Confirm、Skip 或取消本轮，不因经过固定时长而自动确认、跳过或取消。窗口退出沿既有退出确认与清理流程解除等待。

等待期间不发起新的模型请求，不重置本轮请求额度；GUI 保持响应，并保留可用的取消本轮出口。

## 3. 普通非模态反馈窗口（已确认）

使用普通非模态窗口显示请求、输入框及 Confirm / Skip / 取消本轮，不置顶、不锁住其他 LALC 窗口，不妨碍切换游戏。当前 Session 仍处于忙碌状态，禁止切换或新建 Session，也不能并行启动试运行或自动输入。

关闭反馈窗口或按 Esc 只表示 Skip；取消本轮才终止当前轮次。Developer 主窗口退出仍遵循既有退出确认与清理流程，不把退出或取消转换为空答复确认。

## 4. 统一内容与输入组件（已确认）

不区分提问、意见或人工操作类型，也不要求 Agent 提交类型字段。统一展示 Agent 想与用户 / 开发者交互的内容或意图，使用同一个文字输入组件；不在首版增加选项表单、反馈图片附件或操作成功勾选框。

日志记录请求内容、人的选择和答复，以及所属 Session / 轮次 / 工具调用关联；替代旧规格中记录“请求类型”的要求。Confirm / Skip / 取消语义和既有权限边界不变。
