# Developer 模板匹配调试页

2026-11-06，开发者逐项确认设计并授权实现。

## 设计与用法

2026-11-14 起，原 Template Match 与 OCR 独立页合并为 Capture 下方的 **识别调试**页，
顶部标签切换方式。模板匹配、特征匹配（SIFT）、OCR 共用固定原始截图和画布，各自保留选区、参数与结果；切换不重新截图、不执行。
本节替代原独立页用法，后文 2026-11-06 的审查与验证保留历史含义。

模板匹配模式左侧按 Asset 逻辑名组织树，选组匹配整组，选 PNG 叶子只匹配该图；单图按需读取、验哈希并预览。
进入页面或切回模板模式后台增量检查目录及 PNG／标签文件状态，未变不重建树、不清结果；
变化后保留仍存在的选择和展开状态，清除模板与特征匹配旧结果，OCR 状态不受影响。检查不批量读取图片内容，实际预览与匹配仍校验完整哈希。

点击截图只固定新图，不自动匹配。成功后清除两种方式的全部选区与结果，保留匹配参数与素材选择；失败保留旧图及全部状态并报错。
在图上拖选，松开非空选区后自动匹配该区域；没有模板选择时不执行。
“全图匹配”清除模板自己的选区并立即匹配全图，不改变 OCR 选区。
修改模板或参数后只清模板旧结果、不自动运行，可点击“匹配当前选区”重试；没有选区时该按钮禁用，使用“全图匹配”。

右侧设置阈值（默认 0.9）、NMS（默认开启）、NMS IoU 阈值（默认 0.5）及整组优先标签（默认空）。
“匹配参数”标题右侧的“恢复默认”恢复当前模板／SIFT 方式的全部默认参数，清除该方式旧结果；保留截图、选区、素材选择及其他方式参数，不自动重新匹配。后台忙碌时禁用。
画布展示编号框，下方显示可复制分数、原图坐标及图片身份。采用正式原尺寸 BGR 算法、优先标签短路／回退和跨模板 NMS。
本页截图独立于 Capture 素材保存预览；不执行点击，不写素材、Trace 或 Usage Index。匹配失败清本方式旧结果并报错，保留截图与选区；后台活动期间禁用相关操作。

本轮 [确认记录](recognition-lab-decisions.md)、[影响与验证](recognition-lab-impact-review.md)；OCR 用法见 [OCR](ocr.md#developer-识别调试页)。

## 特征匹配（SIFT）

NMS 默认开启，IoU 阈值默认 0.4；整组结果合并后统一抑制重叠框。

选择顶部“特征匹配（SIFT）”，使用同一素材树选择单图或逻辑名整组。整组尝试全部模板，不使用优先标签短路；
各模板尝试查找多个目标，统一按几何内点数降序排列，再按可选 NMS 去重。显示原图编号框，文本提供内点数量、
每个候选投影范围内的内点比例、原图矩形、中心坐标及模板身份。同分按位置和模板哈希稳定排序。
截图不自动执行；框选结束自动匹配，“全图匹配”立即处理全图，“匹配当前选区”用于调参后重试。
两种匹配共用模板选择；选择或素材变化使两者结果失效，调整参数仅清所属方式结果。

右侧可滚动调整：

| 参数 | 默认值 |
| --- | --- |
| 增强前灰度、CLAHE | 开启；CLAHE clipLimit=2、4×4 分块 |
| 放大倍数 | 3；可选 1～5，线性插值 |
| SIFT 特征上限、尺度层数 | 0（不限）、3 |
| 对比度阈值、边缘阈值、sigma、精确上采样 | 0.04、10、1.6、关闭 |
| 特征配对比率 | 0.75：最近距离须小于第二近距离的 0.75 倍 |
| 几何容差 | 原图 4/3 像素；处理时随倍数换算 |
| 最少内点数量、最小比例 | 6、0.4；两者都通过才显示 |
| 目标最小／最大缩放比例 | 0.5／2，相对于原始模板，与处理图放大倍数无关 |
| 最大形变比 | 2；限制投影各角点相邻边所构成变换的最大／最小伸缩比 |
| 最小内点覆盖率 | 0.1；模板与投影目标两侧都须通过，0 可关闭覆盖率过滤 |
| NMS、IoU | 开启、0.4 |

内点指支持同一个几何模型的配对；同一位置的重复方向关键点不重复贡献数量。
比例的分母是当前候选投影内、通过初筛的不同截图特征位置数，不是整屏的配对数。
分数不是概率，也不是模板匹配的 0～1 相似度，不同模板之间不完全可比。

内点覆盖率与内点比例不同：覆盖率用内点围成的凸包面积除以模板／目标投影面积，检查证据是否分布得足够广，
而不是只集中在一角。结果文本分别显示模板和目标覆盖率。提高覆盖率、提高最小缩放、降低最大缩放或最大形变比会收紧过滤，
可能减少错误大框，也可能增加漏检。缩放界限必须最小值不大于最大值；非法组合明确报错。
这些约束在候选被接受及清除其范围内残余配对之前执行，被拒绝的大框不会清空整片区域。

原始截图与素材保持不变，每次从原像素生成处理图，不累计放大或增强。
关闭“增强前转为灰度”时，CLAHE 只增强 Lab 亮度通道；SIFT 本身最终仍提取灰度特征，不提供彩色描述子。
无特征或未达到门槛显示无匹配；坏素材、非法参数或执行异常报错并清当前方式结果，保留截图及选区。
本页不写素材、Usage Index 或 Trace。正式运行可通过 `observe.match_feature` 使用相同 SIFT 算法及默认参数，见[正式用法](developer-workflow-tutorial.md#sift-特征匹配)。

特征查找不承诺零漏检或零误检；全图与局部的 CLAHE 分块不同，结果可能不同。
讨论、实施前影响及实际验证见 [SIFT 记录](feature-match-lab-impact-review.md)。

## 实现前影响审查

- **新增需求**：资源树、按需预览、进入页面的增量检查及固定截图的真实匹配调试。未废弃现有 Capture、OCR 或正式匹配需求，无已确认架构冲突。
- **确认的影响**：`gui.py:MainWindow.__init__/render_state` 显式枚举页面，导航与忙碌状态必须同时接入。原有 OCR 紧跟 Capture 的测试需要允许新页插入。
- **确认的影响**：`developer.py:DeveloperHost.capture(update_preview=False)` 已支持独立截图；`developer_gui.py:OcrView` 已提供原像素框选与编号覆盖层，可直接复用，不修改截图像素。
- **确认的不兼容点**：`assets.py:AssetLibrary.match` 对非空结果无条件写 Usage Index，直接用于调试会污染运行事实。增加默认保留原行为的只读调用选项，调试入口传入关闭值并使用空事件接收器；运行端调用不变。
- **校验边界**：单图入口必须校验逻辑名、完整 SHA-256、归属路径及文件内容。目录扫描不跟随符号链接，读图仍通过 AssetLibrary 的路径与哈希校验。
- **所需改动**：后台入口、专用 GUI 模块、导航、中文翻译、用法／当前状态和针对性测试。现有 Asset／Asset Library 术语足够，无新增领域概念；交互可逆，不新增 ADR。
- **潜在风险**：快速检查依赖文件系统状态，不提供对抗性变更检测或整个素材库的事务快照；扫描中删除文件可明确报错后再次进入重试。低阈值且关闭 NMS 可能产生大量结果。大规模素材库、Windows 包与真实游戏性能需另行验收。
