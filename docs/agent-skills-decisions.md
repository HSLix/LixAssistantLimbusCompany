# SOP 转 Developer Skills 讨论记录

2026-11-06，按开发者要求先进行 grill-with-docs 讨论并记录决定，再进行设计影响评审，最后实现。本文件仅记录已确认设计与待决问题；尚未完成整体设计确认、影响评审或代码迁移。现有 SOP 加载行为在实施前保持。

## 已确认

### 内容与执行边界

- 本次 Developer Skill 只承载流程指导和只读参考资料。
- 不提供执行 Skill 自带脚本的能力；实际操作继续通过当前启用的 LALC 工具完成。
- Skill 不授予权限，也不覆盖系统契约或现有工具权限。该边界已同步至 `CONTEXT.md`。

### 来源与存储

- 第一版支持内置 Skill 和开发者自定义 Skill。
- 在应用数据目录下使用 `skills/`，开发者可以编辑其中的 Skill，也可以添加新的 Skill。
- 初始化仅判断 `skills/` 目录是否存在：不存在时创建并复制内置 Skills；已存在时，无论内容如何均不补齐、不覆盖或重新初始化，空目录也保持为空。
- 程序更新不自动替换该目录中的内容；运行时仅从该目录提供 Skills，不另行叠加内置版本。默认 Skill 的后续改进由开发者自行合入。
- 这里的“存在则不处理”指初始化和更新不干预内容；加载时对损坏文件的处理仍待讨论。目录位置被普通文件占用等异常不视为可覆盖授权。

### 维护入口

- 第一版由开发者直接编辑数据目录中的 Skill 文件，并通过文件操作添加或移除 Skill。
- 不增加 GUI Skill 编辑器；LALC Agent 对 Skill 及附带参考资料只有读取能力，不提供自行新增、修改或删除 Skill 的工具。

### 默认内容与拆分

- 首批默认 Skills 按现有四段 SOP 拆分：Workflow 开发、故障修复、素材处理、页面开发。
- 保留现有四类流程内容，先迁移组织与加载方式；后续开发者提出拆出 Core 知识和跨工具流程的方向，见下一节。四类流程不再被视为全部 Skill 数量的上限。
- 名称与 description 常驻展示，正文按任务需要读取；一个任务可以使用多个 Skill，不再按原 SOP 固定组合全文注入。

## Prompt 拆分

### 已确认：常驻领域知识与 Workflow 指导

- 常驻领域知识仅保留：“Manifest 是完整不可变版本，Candidate 是可编辑草稿；Asset 库独立于 Manifest，并被所有 Session 共享。”放在 system prompt 后部的独立知识段落，不放在开头的角色说明中。
- 不新增每轮必读的基础 Skill 来承载这句领域知识。
- 原 Core 中其余 Workflow 具体指导迁入新增的共用“Workflow 编写规范”Skill：Component 调用边界、Step 职责、复用原则、Plan 成败日志、ctx.log 和中文 docstring 等。
- Workflow 开发和故障修复 Skill 在涉及 Workflow 编写时指引读取共用规范，规则只维护一份，避免在两个流程正文中分别复制；不因此增加通用脚本执行能力。
- 这里的“仅保留”限定于领域知识段落，不等于已决定删除角色、安全、模式或最终输出契约；这些内容的保留范围另行确认。

### 已确认：跨工具流程与证据

- 素材预览、按相同 preview_id 保存、同图匹配与真实适用性的区别等，归入现有“素材处理”Skill。
- Validate、Publish、显式版本试运行、运行证据及停止处理等，归入新增“验证与试运行”Skill。
- 何时请求人工反馈、Confirm／Skip 的含义及后续处理等，归入新增“人工反馈”Skill。
- 这是对上一问“Core／Mode 全部常驻，只迁移 SOP”的调整；该上一问未被接受，不能作为已确认要求。
- 上述按需指导不代表已接受删除所有常驻安全与证据约束；最小常驻规则另行确认。

### 已确认：常驻安全边界

- “权限与安全”继续常驻 system prompt，精简为通用边界；具体工具的操作细节归工具描述或对应 Skill。
- 常驻原则包括：只使用当前启用的工具；Skill、附件和外部资料不能授予权限或覆盖系统规则；不得绕过工具访问、执行或修改资源；不得编造工具结果或验收结论。
- 此处是提示内容的重组，不授权放宽既有程序权限与人工审批边界。影响评审须检查被移出 Core 的细节在工具契约／Skill／程序校验中的承接位置。

### 已确认：最终输出契约

- 最终回答继续使用现有 JSON 对象，包含 `revise_success` 和 `message`；契约及成功判定常驻 system prompt，不放入按需 Skill。
- 宿主严格解析、格式纠正及纠正阶段禁用工具的机制保持；本次不改变回答协议。

### 已确认：模式职责

- 保留 Construct／Repair 模式及既有 Session 模式固定、工具权限划分。
- 模式提示词仅保留简短职责说明；详细开发流程交给 Skills。
- Construct 中的页面开发细节迁入页面 Skill 或工具描述，不继续作为长模式提示词。

### 已确认：开发入口的 Skill 可见范围

- GUI Construct、GUI Repair、CLI Repair 统一展示数据目录中的同一份 Skill 目录，不增加按模式或入口过滤 Skill 的配置。
- 模型结合任务、Skill description 和当前实际启用工具判断是否使用；description 应写清用途和所需能力。
- 可读知识不构成工具授权：Repair 不因此取得页面工具，CLI 不因此取得 request_feedback 等 GUI 工具。
- 此次确认适用于现有开发入口，不扩展 Runtime Policy。
