# Sharing：导出与导入

User GUI → General Settings → Sharing 提供 `Export…` / `Import…`。分享期间持有现有活动与游戏锁，不能同时启动自动化或 Agent。功能用于开发成果分享，不是备份恢复、云同步或外部 Git 仓库迁移。

## 导出

第一步可组合选择以下对象；第二步展示冻结快照的全部实际文件、大小及缺失证据，确认后保存 ZIP。

| 类别 | 内容与默认选择 |
| --- | --- |
| Workflow | 明确选择的完整 Manifest、登记的 Components／Recovery Rules；不推导或附带 Assets |
| Assets | 默认全选，树状选择；每个逻辑名的直属 PNG 与标签是一个不可拆分的组 |
| Extension Pages | 明确选择的页面源码与页内资源，旧单文件包装为 `page.py` |
| Agent History | 默认不选；整段对话、工具日志、基线、导出时的 Candidate／页面草稿和已引用的 Run 证据 |

不进行隐私扫描。向导持续提示：日志、图片、路径和源码可能含私人信息，分享前自行审阅。应用的凭据与私人设置存储不属于分享对象；原日志的既有脱敏保持，不恢复已脱敏内容。不要将私人配置保存在页面资源目录。

## 导入与审查

选择 ZIP 后先检查结构、路径、可用资源、成员登记、SHA-256 与静态依赖，不加载包内 Python，也不调用会导入源码的 Validator。四个 Tab 分别显示对象、检查结果、冲突及保存行为。每个有内容但未查看的 Tab 显示红点；首个有内容的 Tab 默认已查看。红点与选中、检查通过、页面 Review 各自独立，重新检查不重置已查看状态。

必须查看全部有内容的 Tab，至少选择一项，所选内容无阻止错误，并确认不可信来源提示，才能点击统一的 `Import Selected`。

- **Workflow**：下拉切换 Manifest 检查结果，每个版本分别勾选。UUID 占用时分配新 UUID，提交前弹窗展示原、新 UUID 并确认；不覆盖原版本，不改 Default。最终提交重新检查确认的 UUID，再占用则失败，不静默换号。同哈希且同字节的 Component 复用，声明哈希不符视为损坏。即使 Default 的文件缺失，其指向的 UUID 也保留。
- **Assets**：树状勾选，显示冲突组数及文件数，详情默认收起，展开查看所有变动文件及新旧图片／标签。对冲突项选择全部替换或全部跳过，可重新检查。替换仅作用于该逻辑名的直属图片及标签，不删除嵌套独立逻辑组。相同内容跳过。
- **Extension Pages**：左侧多选列表显示独立的未 Review／已 Review／Review 失败状态，点击名称只切换右侧详情。`Review Page…` 显式执行页面预览，沿用 Current／Proposed／Review 三 Tab 和独立内存配置；批准固定版本后返回，不提前写入。统一提交时安装整个页面目录，同名页面整包替换，私人配置保持。未 Review 页面允许安装，但额外弹窗列出名称、确认尚未验证运行身份／加载／接口；已知 Review 失败的页面必须成功重新 Review 或取消选择。安装后提示手动重载，不自动激活。动态声明的 ID 无法由静态检查保证，只有显式 Review 才检查其实际注册结果。
- **Agent History**：保存到 `knowledge/imported-agent-history/<内容哈希>/`，相同完整内容复用。保留完整原始文件，并生成可有界读取的 `readable/` 文本块；大日志图片保留原图，另生成阅读用缩略图。损坏的 Candidate／源码快照作为证据原样保留，不当作日志协议解析。只作为不可信只读参考，不写本地 Session History，不继承权限，不恢复执行或重放工具调用。

提交前再次核对 暂存文件与目标版本。按对象顺序提交，失败停止并列出已完成、失败和未处理内容；已完成对象保留，不承诺跨对象整体回滚。Asset／页面普通替换失败恢复该对象旧内容；若恢复本身失败，保留旧副本并报告路径。不承诺断电／进程崩溃恢复。

## 页面包与 Agent 工具

页面维护自己的目录 `pages/<name>/page.py`，资源如 `assets/banner.png` 通过 `context.resource_path(...)` 定位；配置仍位于包外。普通加载、草稿工具、固定版本预览、安装及 Sharing 共用整包边界。旧顶层 `.py` 和旧 Session 草稿继续可读可改，复制／导出时包装，正式安装或增添草稿资源时转换，不批量迁移。

GUI Construct 的 `page_create`／`page_update`／`page_list`／`page_read`／`page_resource`／`page_preview` 已支持整包。资源工具仅修改当前 Session 草稿的非 Python 资源，来源限明确的页面、Asset、知识库文件，不能访问任意本地路径。Agent 的专用人工审批仍直接安装；Sharing 可跳过 Review 的额外确认不授予 Agent 绕过安装审批的权限。接口示例见[页面说明](../example/pages/README.md)。

## ZIP 格式与资源检查

版本 1 使用根 `sharing.json`：`format="lalc-sharing"`、`version=1`、`objects`。每项含 `kind`、`id`、`files`，每个文件登记 `size` 和 `sha256`，实际内容位于 `objects/<序号>/<相对路径>`。不接受额外未登记文件、重复／大小写别名、显式目录成员、链接、加密或特殊文件；仅支持 stored／deflate。拒绝路径穿越、Windows 非法／保留名及 Git 元数据。

Sharing 的导入／导出和 Agent 页面资源不设置固定对象数、文件数、文件／索引容量、源码／标签大小或图片像素准入上限。此前 1,000／20,000、128／512 MiB、2／16 MiB、36 MP 等阈值已撤销。路径仍须满足既有安全和跨平台命名规则。

选择 ZIP 后先读中央目录和包索引、检查声明及成员登记，然后按声明解压大小和目录开销预检暂存盘与正式数据盘；同盘需求相加，分别检查不同磁盘。新内容准备完成后才替换，旧内容同盘重命名备份，不额外复制旧目录。空间不足即拒绝；系统无法报告剩余磁盘容量时，必须单独明确确认才能跳过该预检。空间预检不是预留，后续写入失败仍按对象事务处理。

文件在 Worker 中分块解压、计算实际大小和 SHA-256，超过声明大小立即停止写入；不符、故障或取消清理本次暂存，不写正式数据。界面提供进度和取消，等待 Worker 安全停止再退出。原生解析／解码期间取消在其返回后的检查点生效。检查完成后审查和提交复用受控暂存，**原 ZIP 删除或变化不影响该固定暂存包**；最终重新核对暂存哈希，不再次解压。应用启动只清理专用暂存区域中活动锁已释放的遗留目录，跳过其他活动实例。

导出及页面审批固定版本使用磁盘副本，哈希、ZIP 写入、资源复制和正式安装以流式文件处理。JSON／Python 语法树等不可避免的内存解析操作按当前可用内存估算需求，资源不足明确失败；不是保证任意规模文件都能被当前机器解析。完整日志逐行处理，引用展开按当前可用内存保护，循环引用继续拒绝，原始证据不截断。生成阅读块时按实际增量检查磁盘空间。

图片仅在展开详情或请求查看时生成预览。解码前根据尺寸估算内存，资源不足只让预览失败，原始文件保持；图片文件本身不因超过固定像素数被拒绝。模型工具返回 JPEG 预览，文本分页返回。分块大小、分页长度、缩略图尺寸是处理／传输单位，不是文件准入限制。Base64 写入受实际内存及模型服务消息容量约束，没有额外的 2 MiB 文件门槛。
