# #336 — 实施前决策确认

2026-10-31：开发者已明确“开始实施”，本轮评审及修订已获确认；当前实现与验证见[实施记录](stage-5-336-implementation.md)。下文等待确认 / 尚未实施的描述保留为审查时点证据。

2026-10-31。本轮关键决策已逐项确认；[专项影响审查](stage-5-336-design-impact-review.md)已完成并等待开发者确认，确认后再进入实现。

## 1. Session 模式与来源的固定时点（已被第 5 项替代）

开发者同意：新建弹窗内可自由调整 Construct / Repair 模式和来源，点击创建成功后两者立即固定。即使尚未发送首条消息，更换模式或来源也必须新建 Session，不重建现有 Candidate 或更换固定基线。

本决定收紧旧文档“开始对话后固定”的表述；Construct 空白来源和 Repair 必须明确已发布来源的规则保持。已同步 Stage 5 规格、ADR 0034、术语及相关决定 / 拆分 / 路线图；远端 #336 将在本轮决策及影响审查收口后统一同步。

## 2. 本票 Construct / Repair 的实际能力（已确认）

开发者同意：两种模式分别定义初始 Prompt 和工具白名单，#336 当前已实现工具集合可以相同。Construct 面向构建与扩展，Repair 聚焦修复；Repair 仍可通过专用工具新增修复所需 Component / Recovery Rule，不增加“Repair 不得新增”的限制。

模型工具声明与宿主分发均按模式及当前入口限权；同集不表示跳过独立策略或从历史恢复授权。#337 知识库、#338 人工反馈、#339 页面工具待各票实现后接入，其中页面构建仅 Construct；未实现工具不提前暴露。

## 3. Developer Selected Manifest 必须为明确版本（已被第 4 项替代）

开发者同意：工作台的版本选择移除“使用 Default”选项，只接受明确的已发布 Manifest ID。保留已有明确选择；没有选择时要求选择，版本失效或刷新失败时明确报错，不自动选 Default、最新版本或其他版本。

此决定替代当前 GUI 在试运行时解析 Default 的便捷行为。Session 切换 / Publish 不改选择；Agent trial_run 同样始终要求明确版本。本轮不迁移旧数据：原“使用 Default”的空选择保持未选择状态。

## 4. 删除 Developer GUI 的 Manifest 选择及手动试运行入口（已确认）

开发者重新评估后明确决定：既然 User GUI 已有方便的启动入口，删除 Developer GUI 的 Manifest 选择及手动试运行区域；不改做“应用到 User GUI”的快捷设置，需要时再实现。

本决定替代工作台右上折叠选择区及本记录第 3 项的界面交付要求；“手动试运行读取何种输入”的建议撤回，未获接受，不进入设计。User GUI 原有普通启动职责保持，不因删除入口而自动切换 Default、改写 Candidate 来源或固定基线。

开发者随后明确确认：保留 Agent 的完整 trial_run 能力，这是 Agent 开发能力的重要部分；本次仅删除 Developer GUI 的人工版本选择和运行入口，User GUI 普通启动保持。Agent 仍可修改、校验、Publish、明确指定已发布 Manifest 及输入试运行，并读取 Run 结果和日志；原有游戏活动互斥、取消收尾和试运行日志窗口保持。

## 5. 首条消息提交时才固定模式与来源（当前决定）

开发者重新明确：选择模式和来源后，应等待用户发送首条消息才固定，不接受“尚未发消息也不能更换”的提前限制。本决定替代第 1 项。

新建后、首条用户消息提交前，模式和来源都可调整；首次提交时，按最终选择确定模式、来源、Candidate 和固定 Diff 基线。开始对话后继续保持不可切换 / 重建；Repair 必须明确已发布来源，Construct 可空白或选已发布来源。

实现建议：将未开始的聊天保留为准备状态，首次发送再原子初始化持久 Session，避免为调整选择增加草稿重建 / 迁移机制。初始化或校验失败不消耗该准备状态；首条消息一旦已提交，不因后续模型错误或取消而解锁来源。此为提交边界的实现建议，不要求等待模型回答成功。
