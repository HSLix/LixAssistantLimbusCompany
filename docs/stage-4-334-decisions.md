# Stage 4 #334：Windows 成品关键决策

状态：2026-10-28 grill 已结束；2026-10-30 开发者确认继续实施，接受影响评审方案。当前本地实现及未验收边界见[实施记录](stage-4-334-implementation.md)，Windows 构建与现场验收说明见[构建文档](windows-packaging.md)。#334 尚未关闭。

## 已确认

- Windows x64 采用现有 PyInstaller `onedir` 文件夹版，以 ZIP 交付；解压后运行，无需安装 Python。本票不增加安装器或单文件封装。
- 提供两个 ZIP：一个附带 Windows pi，另一个不附带 pi。优先使用随包 pi 路径，再回退到既有环境路径查找。
- 随包 pi 文件缺失、无法启动、版本探测失败或 RPC 尚未就绪便退出时，允许在模型请求和工具执行开始前回退一次到环境路径，并记录原因。版本不同沿用既有规则，仅警告；模型请求或工具执行开始后发生错误，保留错误并结束本轮，不换进程重跑。
- 程序 ZIP 暂不附带可修改数据。未来另设导出功能，将一套可用的可修改数据导出为 ZIP，供他人下载、导入；数据导出/导入功能不在本票实现。
- Windows 成品运行时的可修改数据统一保存在 `%LOCALAPPDATA%\LALC`，与程序解压目录分离；包括配置、日志、Manifest、Assets、外置 `pages` 和 Developer `candidate`。
- 示例数据留在仓库，提供开发者验收准备步骤，在测试机单独部署；两个程序 ZIP 均不带示例数据，首次启动不自动生成，不实现正式导入功能。
- 除 pi 外，两包应用内容保持一致，并由构建检查核对。通用 Windows 成品验收仅需选择其中一个包执行；pi 的选择、回退与缺失行为分别覆盖两个包，无需重复全套通用验收。
- 提供可复现的 Windows 本地构建脚本，一次生成两个 ZIP，并记录源码版本和依赖版本。GitHub Actions 在 Stage 6 完成后才考虑，本票不加入。
- 2026-10-30 补充：构建输入集中放在源码根目录 `pi_resources/`（已加入 .gitignore）；默认读取其中 `pi-windows-x64.zip`，也允许构建参数指定归档位置。保留原始 ZIP，由构建脚本校验并自动组装，无需用户手动解压。开发者已提供该目录中的 Windows pi 1.4.0 原始归档。
- 回归测试不调用真实模型；Windows 上的真实模型验证不纳入本票事项，不作为 #334 关闭门槛。上一轮提出的“真实 Windows pi + HTTP 替身作为必需验收组合”未获确认，不列为接受要求；相关 Agent 测试仍遵守仓库的显式选择与证据分层规则。本决定不取消 #334 原有的 Windows 成品功能验收。
