# Sharing 设计讨论记录

当前本地实现及最终规则见 [Sharing](sharing.md) 和 [ADR 0036](adr/0036-share-selected-objects-and-install-complete-page-packages.md)，验证见[实施记录](sharing-implementation-progress.md)。本文保留讨论／审查历史，早期 Manifest 覆盖、独立草稿导入等方案已由后续决定替代。

状态：2026-11-04 开发者在 Manifest 不覆盖及冲突分配新 UUID 修订后明确“同意，开始实施”，并要求控制单批范围、保存可接续状态。现已完成本地实现及回归，见[实施记录](sharing-implementation-progress.md)。下文按时间保留讨论演进，早期“待确认”不推翻后续明确确认；当前目标以最终汇总、最新修订及[影响审查](sharing-design-impact-review.md)为准。

## 2026-11-03 已确认

- User GUI General Settings 增加 Sharing 导入、导出入口，三张截图作为交互参考。
- 导入显示全部冲突文件及数量，详情默认收起，图片详情支持新旧预览；提供重新检查、全部替换和全部跳过。
- Asset 重复项按逻辑名整组处理，比较图片集合及标签。本地 A、B 与包内 B、C：替换后的活动集合为 B、C；跳过保持 A、B。旧图片的保留方式待确认。
- 导入接入现有运行／活动互斥，不允许自动化运行期间提交。已撤回运行中通过 GUI 导入的场景。

## 2026-11-04 已确认

- 全部替换仅适用于 Asset，不推广为所有对象的统一覆盖操作。
- Workflow Tab 使用下拉框选择包内 Manifest，显示所选版本的检查结果，重点检查 Manifest UUID 是否占用。
- Component 允许不同 Manifest 使用相同逻辑名；相同哈希且内容一致时复用，不覆盖。内容与声明哈希不符视为损坏。
- Manifest UUID 冲突允许人工确认覆盖；导入确认须明确说明会完全删除原 Manifest 并以包内 Manifest 替换。该决定是导入入口对既有不可变 Manifest 规则的拟新增人工例外，尚待确认 Default 等关联状态的处理；不授予 Agent 覆盖权限。
- 允许覆盖当前 Default 指向的 UUID。确认须突出说明该版本正在作为 Default，覆盖后下次运行将使用导入内容；本次明确确认批准此变化，不自动运行。该决定细化原草稿“不修改 Default”：UUID 选择保持，指向的内容允许按人工确认替换。
- 页面使用下拉框选择，接入普通页面 Preview / Review 安装流程。该决定修订了草稿中仅导入未安装草稿的交互，具体预览时机和与统一 Import Selected 的关系待确认。
- 后续截图修订页面选择布局：Extension Page 使用左侧页面列表及勾选框、右侧当前页面详情与 Review Page 入口，替代页面下拉框。左侧每个页面须单独标识是否 Review；选中导入、当前查看及 Review 状态分别表达。用户要求 Import Selected 应用于左侧勾选页面；Review 是否仅批准待提交版本、最终提交是草稿导入还是正式安装仍待明确。截图底部的演示文字不作为业务行为的已确认决定。
- 最终页面提交选择 A 并作修订：Review Page 仅审查并批准固定页面版本，不立即安装；Import Selected 统一安装勾选页面。Review 非强制：有勾选但未 Review 的页面时，提交前另弹提示，列出这些页面并明确询问是否继续安装；该次明确确认可授权安装未 Review 页面。已 Review、未 Review 与检查／Review 失败分别显示，不把失败伪装成未审查。具体阻断检查仍需设计及影响审查，不把跳过 Review 解释为绕过包结构／路径／哈希检查的授权。
- 页面资源直接采用每页独立资源文件夹；不采用 Base64 嵌图的单文件过渡方案。导入覆盖按该页面文件夹全量替换，不能只替换源码或把旧资源与新资源合并。该决定扩展既有单文件页面契约，需要同步调整页面发现、草稿、预览版本绑定、安装及测试；具体目录布局尚未定案。
- 接受新页面使用独立目录，源码及资源共同构成版本；Review 绑定整个目录内容，资源变化使原 Review 失效。用户配置保持目录外存储，不随页面整包替换。
- 旧单文件页面继续可读；新建页面统一目录格式。旧页导出时封装为目录，安装新版后替换对应旧文件，不自动批量迁移。
- 用户明确要求：目录化对现有 page 工具的影响必须全部处理。影响审查及实施范围须包括 Agent 页面工具及其声明／提示、Session 草稿持久化、普通页面加载、预览审查、安装、导入导出、相关文档与测试；不得只完成 Sharing 界面而留下旧工具不可用。
- Agent History 按完整对话选择并导出，支持多选，首版不做逐轮裁剪；默认不勾选。包含完整聊天、工具记录及其引用的日志／证据，导入外部知识库后仅只读查阅，不进入本地可恢复 Session History，不能续聊、恢复执行或重放工具。Candidate 快照及隐私审查细节继续讨论。
- 已确认默认随所选对话携带初始基线、导出时 Candidate 快照及该 Session 的页面草稿和资源，导出审查列出完整文件清单。明确标记为导出时快照，不声称是历史轮次的精确版本；日志已有的历史版本证据保留。导入后这些附带文件仅为知识库参考，不注册 Workflow、不安装页面、不创建可恢复 Session。
- 用户明确取消新增导出隐私检查：不实现隐私扫描、疑似敏感信息检测、自动隐私判定或相关阻断门槛；导出界面须提示注意隐私泄露。此前提出的扫描／阻断／人工逐项隐私审阅方案未被接受。仍保留现有日志已完成的脱敏，不为导出恢复秘密；私人配置及凭据文件不属于分享对象或必要依赖，不加入导出清单。提示不能宣称已自动检查安全。
- Asset 从 Workflow 分享内容中分离，成为独立导入／导出类别。不实现基于 Workflow 的 Asset 依赖分析、自动预选或调用链推导。Asset 导出默认选中本地全部 Asset，导入默认选中包内全部 Asset，均支持树状选择。
- Workflow 导出只包含所选 Manifest 及其登记的 Component／Recovery Rule 源码，不隐式携带 Asset；导入 Workflow 不以自动分析 Asset 是否完整作为检查门槛。Asset 的整逻辑名替换／跳过及新旧图片审查决定继续保留。
- 用户明确本次取舍目的：减少实现成本及低收益设计。分类由原三类扩展为 Workflow、Asset、Extension Page、Agent History；具体审查导航及树的叶节点选择粒度待确认。
- 已确认 Asset 树以完整逻辑名为最小勾选单位；路径父节点可批量勾选子项，每个逻辑名下的图片集合与标签整组携带。图片可以展开预览，但不单独勾选，以保持整组替换／跳过语义。助手提出四个审查 Tab，导航细节尚未单独确认。
- 已确认逐对象提交、失败即停止：单个 Manifest、Asset 逻辑名组或页面目录先准备完整内容再提交替换，普通提交失败保留该对象旧内容；此前成功对象保留，不做跨类别整体回滚。结果明确列出已完成／失败／未处理，用户可重新检查后重试。该决定不承诺撤销人工 Preview 执行的 Python 副作用，也不等同于已验证断电／进程崩溃恢复。

## 收尾汇总待确认

- 审查导航使用 Workflow、Assets、Extension Pages、Agent History 四个 Tab，沿用原先按非空类别计数的未查看红点规则。Tab 已查看不代表页面已 Review。
- 重新检查更新结构／哈希／目标占用及冲突结果；不能沿用不再匹配的覆盖确认或整包 Review。相同页面整包版本的 Review 可保留，Tab 红点仍只表示是否查看过，不改为错误／冲突标识。
- Import Selected 统一提交选中对象；页面 Review 仅批准待提交的固定整包版本。跳过页面 Review 的额外安装确认仅限 Sharing 人工导入，不授予 Agent 跳过 page_preview 的安装权限。

## 影响审查需落实的实现事项

- Manifest UUID 占用时分配新 UUID 并明确确认；具体规则见下文最新修订，不再实施同 UUID 覆盖或为此刷新既有 Default 内容。
- 页面具体目录契约及资源读写工具接口；未 Review 安装可完成的非执行式检查范围。
- 外部 Agent History 的只读接入细节（不新增隐私检查）。
- Asset／页面旧目录仅用于单对象安全替换期间的恢复，不新增面向用户的备份／版本管理功能；具体提交机制及故障保证由影响审查明确，不把普通异常回退冒充崩溃恢复。
- 重检后的查看状态、提交一致性、失败恢复及包格式安全边界。

## 影响审查后修订：Manifest 不覆盖

本节取代上文所有允许 Manifest UUID 覆盖、包括覆盖当前 Default 的决定；其他类别决定保持。

- 本地已有 Manifest 不因导入而覆盖或删除，保持本地 UUID 与 Manifest 内容映射稳定。
- 导入 UUID 未占用时保留来源 UUID；已占用时，无论内容是否相同，先为待导入对象分配新 UUID，弹窗显示原 UUID、新 UUID，并询问是否继续导入。取消不导入该对象；用户已确认的新 UUID 不能在最终提交时静默改成另一个。
- 弹窗在最终导入流程中确认，提前分配 UUID 不等于创建本地 Manifest；最终提交以排他创建落盘，不允许覆盖竞争写入的文件。再次占用时只需写入失败并报错，不静默换号，不设计专门的再次冲突交互流程；这是用户后续已同意的简化。
- 只修改本地导入副本的 `manifest_id`；Component 内容、哈希和登记关系不变，复用相同哈希源码；来源 ZIP 及其完整性验证不变。导入结果保留原 UUID→新 UUID 的对应说明，不把额外来源字段塞入现有 Manifest schema。
- 不修改 Default，不改既有 Run／Session／历史附件，也不继承来源包自称的批准权限；外部 Agent History 保持来源事实，不为新本地 UUID 批量改写历史。
- 本节最初仅修订设计／审查；后续开发者已明确批准开始分批实施，当前进度见文首链接。

## 2026-11-04 后续资源规则修订

开发者明确同意 Sharing 导入和导出全部取消固定数量／大小／像素准入上限，采用可用资源检查、流式文件处理和按需预览；Agent 页面资源的 2 MiB 固定上限同时撤销。附件规定的索引优先、分盘空间预检、可取消 Worker 一次暂存、大小／哈希核验、复用暂存提交及有限域遗留清理纳入实现。分页／块／预览尺寸继续作为处理单位，私人配置、权限、单对象事务及非执行校验规则保持。见 [ADR 0037](adr/0037-budget-sharing-against-available-resources.md) 和[影响审查](sharing-resource-impact-review.md)。
