# 单个运行日志的展示与传输

2026-11-08：经逐项设计确认，用户授权影响审查后实现。仅替代 user-run-logs.md 的列表命名、排序及传输入口；原有分页、筛选、快照接受、全文搜索和按需看图约定继续有效。

## 接受的设计

- 中文标题为“79 号日志”，英文为“Log No.79”；左侧显示原始开始时间到小时，右侧显示到秒，均按本地时区。开始时间取 Trace 首条有效带时区事件时间，缺失显示“—”，不使用导入时间替代。
- 左侧“全部／本机／导入”分类和导入按钮，右侧所选日志标题、时间和导出按钮。按原始开始时间倒序排列，未知时间放末尾。
- 单日志 ZIP 包含完整 Trace 和其引用的本次运行原始截图，不包含工作流源码、素材库、Agent 对话。缺图继续显示原有占位；筛选、阅读位置不影响导出内容。
- 运行中的日志可导出：点击时固定最新完整换行记录边界，后续追加与半行不进入包。
- 导入选 ZIP 后直接显示可取消进度弹窗，自动校验格式、路径、大小、哈希，不显示人工审查页；全部成功后一次提交并提示完成，取消清理暂存。
- 导出先压缩（可取消），进度窗关闭后打开系统另存为对话框保存 ZIP；保存阶段流式复制，可取消，失败不破坏已有目标。
- 导入日志保留原编号、事件时间和截图，以随机导入身份独立存放，不改本机 run-sequence.json；同编号不会覆盖，重复导入保留独立记录，允许再导出。不恢复执行或 Session。

## 实施前影响审查

已确认：RunLogPage 原列表从 traces/*.jsonl 生成 Run #编号，以编号排序，所有读取使用同一个数据根目录。同编号外部日志直接写入本机目录会覆盖记录、混淆截图，且影响后续编号分配。因此需要独立导入根和独立选择身份；阅读器仍使用原始数字编号。

可复用：run_logs.py 的固定完整记录边界、分页、证据解析；sharing_gui.sharing_task 的 Worker、模态进度、取消和清理等待；file_content 的流式校验、容量检查与取消检查。现有 SharingPackage 仅支持四种分享对象及审查流程，不能直接充当无审查的单日志传输入口；本次采用独立 lalc-run-log v1 格式，不扩大原分享对象种类或权限。

影响路径：列表枚举 → 来源筛选 → 独立身份选择 → 原阅读器／图片读取；导出快照 → 引用截图 → 哈希索引 → ZIP → 系统保存；导入 ZIP 索引预检 → 路径白名单与哈希检查 → 同盘暂存 → 原子目录提交。源 Run 编号和本机执行分配器保持分离。

## 文件与边界

- 新模块 run_log_sharing.py；GUI 接入 run_log_gui.py；中英文 .ts/.qm 和领域术语同步。
- ZIP 内含 run.json、traces/<源编号>.jsonl、evidence/<源编号>/<截图编号>.png 或 .avif；run.json 记录格式、版本、原编号及文件大小／SHA-256。只接受这些路径，拒绝额外文件、重复成员、链接、目录成员、加密及不支持的压缩方式。2026-11-12 新增 AVIF 证据支持，旧程序可能无法导入含 AVIF 的新包；既有 PNG 包保持可读。
- 导入最终目录为 数据目录/imported-run-logs/<导入 UUID>/，内保持相同布局；本机 traces、evidence、runs、ledger 均不改写。
- 无固定文件数量、字节数、图片像素门槛，按当前内存／磁盘预算检查并流式处理。ZIP 索引解析仍受实际可用内存限制。导入数据只读浏览，不执行任何包内内容。
- 大型目录枚举要读取各日志的首个有效时间，尚无持久索引；超大日志库性能和 Windows 原生文件对话框待现场验证。
